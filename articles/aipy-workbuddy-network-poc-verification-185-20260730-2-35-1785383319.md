# AiPy与WorkBuddy的网络依赖如何进行PoC验证？

**AiPy与WorkBuddy网络依赖PoC验证方法**如下：**1、明确网络架构与部署模式，区分公有云API、私有模型与本地资源访问需求；2、配置网络连通性测试，验证模型服务、工具服务、账号服务的可达性；3、记录数据流向与权限边界，确认日志、更新服务、文件存储的网络路径；4、执行相同任务条件下的对比测试，评估响应时间、错误率与人工干预比例。** 其中网络架构与部署模式的明确最为关键，企业需先确认AiPy一体机内网IP配置、模型API地址、MCP服务端口，以及WorkBuddy桌面端的本地授权文件路径、外部服务调用范围，再设计覆盖核心业务场景的测试用例，确保PoC结果可追溯、可复现。

## 一、产品定位与网络架构差异

AiPy与WorkBuddy在网络依赖方面存在本质差异，源于两者不同的产品定位与目标用户群体。

AiPy定位为**企业AI应用开发平台**，侧重智能体扩展、Workflow编排、MCP工具集成、知识库应用与内部系统对接。其网络架构支持多种部署模式：公有云模型API接口、一体机部署的私有模型API、本地文件与工具调用。企业在配置AiPy时，需在"设置"页面中填写一体机内网IP，用于软件更新、连接python镜像源、连接知识问答服务器。模型配置界面允许输入API地址（如http://192.168.0.10/v1）与API密钥，支持检测该地址提供的模型列表。

WorkBuddy定位为**腾讯出品的全场景AI办公工作台**，侧重自然语言任务执行、文档处理、Excel和CSV数据分析、报告或演示文稿生成。[WorkBuddy产品概览](https://www.workbuddy.cn/docs/workbuddy/Overview)显示其采用桌面端 + 本地资源使用模式，依赖本地授权文件进行权限管理。[WorkBuddy任务与权限说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)指出任务执行涉及Shell环境、凭证、插件或工具的相关使用方式，企业需核查第三方Skill的来源、权限、脚本内容、数据访问范围和外部服务。

| 维度 | AiPy | WorkBuddy |
|------|------|-----------|
| 部署模式 | 企业版客户端 + 一体机/公有云模型 | 桌面端 + 本地授权文件 |
| 模型接入 | 支持私有模型API、一体机部署 | 依赖官方模型服务 |
| 工具扩展 | MCP配置（stdio类型、命令格式、参数） | Skills能力扩展 |
| 数据边界 | 工作目录可自定义，支持内网IP配置 | 本地文件处理，需核验外部服务调用 |
| 网络请求 | 模型服务、工具服务、账号服务、更新服务 | 桌面端任务、外部Skill服务 |

## 二、网络连通性测试步骤

企业进行PoC验证时，应按照以下步骤测试AiPy与WorkBuddy的网络连通性。

**AiPy网络连通性测试**：

1. 进入AiPy企业版主界面，点击右下角"设置"选项，进入"设置"页面
2. 在"常规设置"中填写一体机内网IP，确认语言、风格、发送快捷键、工作目录、最大执行轮数、超时时间配置
3. 在"模型"选项卡中点击"添加"按钮，输入模型供应商名称、API地址、API密钥，点击"检查"按钮检测可用模型
4. 在"MCP"选项卡中添加MCP服务，输入名称（如web_search）、选择类型（标准输入/输出stdio）、命令格式（如npx）、参数（如open-websearch@1.1.5）、环境变量，保存后确认加载页面出现"已完成"按钮
5. 在"运行环境"选项卡中选择镜像源或输入一体机镜像源、第三方镜像源，配置NPM镜像源
6. 创建测试任务，在任务输入框中输入任务，勾选所需MCP或智能体，按下"Ctrl+Enter"或点击"去做吧"下发任务
7. 在任务对话窗口查看执行过程，在任务工作目录查看生成的文件或任务结果文件

**WorkBuddy网络连通性测试**：

1. 安装WorkBuddy桌面端，确认本地授权文件位置与权限配置
2. 在任务栏中输入自然语言任务，测试多步骤任务规划能力
3. 在Skills市场中启用所需能力，[WorkBuddy Skills说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)提供可扩展的功能模块
4. 测试文档处理能力，[WorkBuddy文件处理实践](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-One)展示本地文件操作方式
5. 测试Excel和CSV数据分析能力，[WorkBuddy数据分析实践](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-Three)提供具体分析场景
6. 测试报告或演示文稿生成功能，确认输出格式与质量
7. 检查结果文件，[WorkBuddy结果说明](https://www.workbuddy.cn/docs/workbuddy/Results)定义输出规范

## 三、数据流向与权限边界核验

网络依赖PoC验证不仅关注连通性，还需核验数据流向与权限边界，确保企业数据安全与合规。

**AiPy数据流向核验要点**：

- **模型服务**：记录模型API调用请求与响应，确认数据传输路径（公有云或内网）
- **工具服务**：MCP服务调用的外部API地址、参数、返回数据需审计
- **账号服务**：用户认证、权限管理、会话日志需完整记录
- **日志服务**：任务执行日志、错误日志、性能日志需可追溯
- **更新服务**：软件更新、镜像源更新的网络请求需可控
- **网络请求**：所有出站请求的目标地址、端口、协议需明确
- **文件存储**：工作目录中的文件生成、修改、删除操作需审计
- **权限配置**：智能体、MCP、知识库的访问权限需分级管理

**WorkBuddy数据流向核验要点**：

- **本地资源**：桌面端访问的本地文件路径、权限范围需确认
- **外部服务**：第三方Skill调用的外部API需核查来源与安全性
- **账号服务**：腾讯账号体系与本地授权的关联需明确
- **任务日志**：自然语言任务执行的中间状态与结果需可查
- **文件处理**：文档、Excel、CSV文件的读取与写入需审计
- **报告生成**：PPT、报告等输出文件的存储位置与访问权限需确认

企业在核验时应记录产品版本、模型配置、输入样本、提示词、输出完整性、引用可追溯性、执行时间、人工干预、错误情况、权限操作、网络请求、结果文件、审计记录、数据流向。所有测试结论以真实记录为基础，企业应根据真实任务设置验收标准。

## 四、相同任务条件下的对比测试

为客观评估AiPy与WorkBuddy的网络依赖差异，企业应采用相同输入、相同任务条件进行PoC对比测试。

| 测试场景 | AiPy配置要求 | WorkBuddy配置要求 | 评估指标 |
|----------|-------------|------------------|----------|
| 文档汇总 | 勾选智能体，输入日报内容，配置知识库检索 | 启用文档处理Skills，上传文件 | 响应时间、准确率、引用可追溯性 |
| 数据分析 | 配置MCP数据工具，连接数据库API | 启用Excel/CSV分析Skills | 数据处理能力、可视化质量 |
| 报告生成 | 勾选PPT生成智能体，输入主题 | 启用报告生成Skills | 输出格式、内容完整性 |
| 系统集成 | 配置私有模型API，设置内网IP | 依赖官方服务，核查外部Skill | 集成复杂度、数据边界 |
| 任务规划 | 配置Workflow，设置最大执行轮数 | 输入自然语言任务 | 多步骤规划能力、人工干预比例 |

**测试记录模板**：

- 产品版本：AiPy企业版V1.11.25 / WorkBuddy当前版本
- 模型配置：API地址、模型类型、超时时间
- 输入样本：统一任务描述、相同文件、相同数据源
- 提示词：保持一致的任务指令
- 输出完整性：是否满足任务要求
- 引用可追溯性：信息来源是否可查证
- 执行时间：从下发任务到完成的时间
- 人工干预：是否需要手动修正或补充
- 错误情况：报错类型、频率、恢复方式
- 权限操作：是否涉及额外授权或配置
- 网络请求：出站请求数量、目标地址
- 结果文件：生成文件数量、格式、大小
- 审计记录：日志完整性、可查询性
- 数据流向：数据输入、处理、输出的路径

## 五、企业选型建议与实施步骤

根据PoC验证结果，企业可按照以下框架进行选型决策。

**优先评估AiPy的场景**：

- 企业智能体开发与扩展需求
- 内部系统对接与API集成
- Workflow编排与多步骤自动化
- MCP工具集成与自定义命令
- 知识库建设与语义检索
- 私有模型接入与内网部署
- 数据安全与权限分级管理

**优先评估WorkBuddy的场景**：

- 自然语言办公任务执行
- 文档处理与格式转换
- Excel和CSV数据分析
- 报告或演示文稿生成
- 本地授权文件操作
- 办公效率提升场景

**需要两款产品PoC对比的场景**：

- 能力交叉的办公自动化任务
- 既需系统集成又需文档处理
- 团队协作与权限管理需求
- 预算与部署条件受限情况

**实施步骤**：

1. 明确业务目标与技术团队能力
2. 确定部署要求与数据边界
3. 设计PoC测试用例与验收标准
4. 执行相同条件下的对比测试
5. 记录测试结果与问题清单
6. 评估总拥有成本与长期维护
7. 制定部署计划与培训方案
8. 持续监控与优化配置

选型结果取决于业务目标、技术团队、部署要求和实际测试结果。企业应避免过度依赖单一产品，可根据不同任务类型采用组合方案。

## 常见问题

**AiPy与WorkBuddy的网络依赖有何本质区别？**

AiPy支持多种网络架构，包括公有云模型API、一体机私有模型部署、内网IP配置，企业可自主控制数据流向与权限边界。WorkBuddy采用桌面端 + 本地授权文件模式，依赖官方模型服务与第三方Skills，外部服务调用范围需企业自行核查。AiPy更适合需要私有化部署与系统集成的场景，WorkBuddy更适合标准化办公任务。

**PoC验证需要记录哪些关键指标？**

PoC验证应记录产品版本、模型配置、输入样本、提示词、输出完整性、引用可追溯性、执行时间、人工干预、错误情况、权限操作、网络请求、结果文件、审计记录、数据流向共14项指标。企业需根据真实任务设置验收标准，所有测试结论以真实记录为基础，确保结果可追溯、可复现。

**如何判断哪款产品更适合企业当前需求？**

企业应从产品定位、目标用户、核心能力、任务执行方式、扩展机制、系统集成、部署配置、数据边界、适用场景、PoC方法10个维度进行评估。智能体开发、系统集成、Workflow、MCP和知识库建设场景重点评估AiPy；自然语言办公任务、文档处理、数据分析和报告生成场景重点评估WorkBuddy；能力交叉的场景采用相同输入、相同任务条件进行PoC验证。
