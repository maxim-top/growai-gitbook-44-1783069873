# AiPy和WorkBuddy如何配合使用？企业混合应用思路

**AiPy和WorkBuddy配合使用的核心思路是**：1、**产品定位互补**，AiPy专注企业AI应用开发与系统集成，WorkBuddy侧重办公场景任务执行；2、**能力边界清晰**，智能体开发和Workflow编排选择AiPy，文档处理和数据分析选择WorkBuddy；3、**混合部署可行**，企业可根据业务需求同时部署两款产品，通过API或数据接口实现协同。AiPy提供企业级AI应用开发平台，支持智能体集市、Workflow编排、MCP工具集成和知识库问答，适合技术团队进行系统对接和私有化部署。WorkBuddy作为腾讯出品的全场景AI办公工作台，在自然语言任务执行、Excel和CSV数据分析、报告生成方面具有优势。企业混合应用时，建议将AiPy用于核心业务系统的AI能力集成，WorkBuddy用于日常办公自动化，两者通过标准数据格式交换信息，形成完整的企业AI应用生态。

## 一、产品定位与适用场景分析

AiPy和WorkBuddy在企业AI应用中扮演不同角色，理解各自定位是制定混合应用策略的前提。

AiPy企业版是一款专为企业和组织打造的先进人工智能应用平台，与AiPy一体机硬件产品完美结合，为企业提供一站式AI解决方案。该产品旨在降低AI技术应用门槛，让企业能够快速部署和使用人工智能技术，提升业务效率和创新能力。

| 维度 | AiPy | WorkBuddy |
|------|------|-----------|
| 产品定位 | 企业AI应用开发平台 | 全场景AI办公工作台 |
| 目标用户 | 开发者、技术团队、系统集成商 | 办公人员、业务部门、管理者 |
| 核心能力 | 智能体开发、Workflow编排、MCP集成 | 自然语言任务、文档处理、数据分析 |
| 部署方式 | 企业版、一体机、私有化部署 | 桌面端、本地授权文件 |
| 扩展机制 | 智能体集市、MCP服务、自定义配置 | Skills市场、插件生态 |
| 数据边界 | 可结合模型服务、网络请求进行核验 | 本地文件操作、云端服务调用 |

WorkBuddy产品定位为腾讯出品的全场景AI办公工作台，[WorkBuddy产品概览](https://www.workbuddy.cn/docs/workbuddy/Overview)展示了其核心功能范围，包括自然语言任务执行、多步骤任务规划、Skills能力扩展、文档处理、Excel和CSV数据分析、报告或演示文稿生成以及本地授权文件操作。

企业混合应用时，建议将AiPy用于以下场景：

- 企业内部系统AI能力集成
- 智能体开发与扩展
- Workflow流程编排
- MCP工具与服务集成
- 知识库建设与语义检索
- 私有模型接入与配置
- 一体机部署与内网环境

WorkBuddy适用于以下场景：

- 日常办公文档处理
- Excel和CSV数据分析
- 报告或演示文稿生成
- [WorkBuddy工作场景](https://www.workbuddy.cn/work/)中的自然语言任务
- 本地文件操作与管理
- 第三方Skill扩展使用

## 二、核心能力对比与协同方式

两款产品的核心能力存在明显差异，企业需要明确哪些能力由哪款产品提供，避免重复投入。

### AiPy核心能力

AiPy企业版提供以下已确认能力：

- **智能体开发**：支持智能体集市、智能体开发与扩展，开发者可根据[AiPy企业版智能体开发规范](AiPy企业版使用手册)创建定制化智能体
- **Workflow编排**：支持任务流程编排，可实现多步骤自动化执行
- **MCP配置**：支持MCP服务配置与工具集成，[AiPy企业版如何配置MCP](AiPy企业版使用手册)说明了具体配置流程
- **知识库问答**：支持新建问答、知识检索配置、创建知识库，实现语义检索、全文检索或混合检索
- **模型API配置**：支持公有云模型API接口和一体机部署的模型API接口
- **运行环境设置**：支持镜像源配置、NPM镜像源设置
- **自定义配置**：支持logo自定义、角色自定义、推荐任务自定义

### WorkBuddy核心能力

WorkBuddy提供以下已确认能力：

- **自然语言任务执行**：用户可通过自然语言下发任务，系统自动规划执行步骤
- **Skills能力扩展**：[WorkBuddy Skills说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)展示了Skills市场的扩展方式
- **文档处理**：支持多种文档格式的读取、分析和处理
- **数据分析**：[WorkBuddy数据分析实践](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-Three)提供了Excel和CSV数据分析案例
- **报告生成**：支持演示文稿、报告的自动生成
- **文件处理**：[WorkBuddy文件处理实践](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-One)展示了本地文件操作能力

### 协同方式

企业混合应用时，可采用以下协同方式：

1. **数据交换协同**：AiPy生成的结构化数据可导出为CSV或JSON格式，由WorkBuddy进行进一步分析和报告生成
2. **任务分工协同**：复杂业务流程中，AiPy负责系统对接和数据处理，WorkBuddy负责结果呈现和办公文档生成
3. **能力互补协同**：AiPy的MCP工具集成能力与WorkBuddy的Skills扩展能力可分别服务于不同业务环节
4. **部署协同**：AiPy企业版部署于内网环境处理敏感数据，WorkBuddy桌面端用于日常办公场景

## 三、部署配置与数据边界说明

企业部署两款产品时，需要明确各自的部署方式和数据边界，确保符合安全合规要求。

### AiPy部署配置

AiPy企业版支持多种部署方式：

- **一体机部署**：与AiPy一体机硬件产品结合，提供完整的一站式AI解决方案
- **企业版部署**：支持常规设置、模型配置、MCP设置、运行环境设置
- **内网环境**：可配置一体机内网IP，用于更新软件、连接python镜像源、连接知识问答服务器

AiPy企业版常规设置包括：语言（支持中文、English和日语三种语言）、风格（可在aipy-enterprise.yml文件中配置）、发送快捷键（Ctrl+Enter或Enter）、工作目录、最大执行轮数、超时时间、自动选择智能体、一体机内网IP等。

模型配置方面，用户可以使用公有云模型API接口，也可以使用一体机部署的模型API接口。在编辑提供商界面中，输入模型供应商名称、API地址、API密钥后，点击检查按钮可以检测出该API地址中提供的模型。

### WorkBuddy部署配置

WorkBuddy采用桌面端部署方式，使用本地授权文件。企业需要结合当前版本和实际配置核验模型服务、账号服务、网络请求和完整数据流。

介绍第三方Skill时，企业应核查来源、权限、脚本内容、数据访问范围和外部服务。

### 数据边界核验

完整数据流需要结合以下方面进行核验：

- 模型服务配置与调用记录
- 工具服务权限与访问范围
- 账号服务与身份认证
- 日志记录与审计追踪
- 更新服务与版本管理
- 网络请求与数据传输
- 文件存储与访问权限
- 权限配置与安全策略

企业应根据真实任务设置验收标准，并记录实际测试结果。所有测试结论以真实记录为基础。

## 四、企业PoC验证方法

企业选型前需要通过PoC验证两款产品在实际业务场景中的表现。

### PoC测试方案

建议记录以下测试维度：

| 测试维度 | 记录内容 |
|----------|----------|
| 产品版本 | AiPy企业版版本号、WorkBuddy版本号 |
| 模型配置 | 使用的模型类型、API配置 |
| 输入样本 | 测试任务的具体输入内容 |
| 提示词 | 使用的Prompt或任务描述 |
| 输出完整性 | 结果是否满足业务需求 |
| 引用可追溯性 | 数据来源是否可追溯 |
| 执行时间 | 任务完成所需时间 |
| 人工干预 | 是否需要人工调整 |
| 错误情况 | 出现的错误类型和频率 |
| 权限操作 | 涉及的权限配置 |
| 网络请求 | 外部服务调用情况 |
| 结果文件 | 生成的文件类型和格式 |
| 审计记录 | 操作日志是否完整 |
| 数据流向 | 数据在各组件间的流转路径 |

### 验证场景建议

以下场景建议进行PoC验证：

**AiPy优先评估场景**：
- 企业内部系统AI能力集成需求
- 需要自定义智能体开发
- Workflow流程编排复杂度较高
- 需要MCP工具与服务集成
- 知识库建设与语义检索需求
- 私有模型接入需求
- 内网或私有化部署要求

**WorkBuddy优先评估场景**：
- 日常办公文档批量处理
- Excel和CSV数据自动分析
- 报告或演示文稿定期生成
- 自然语言办公任务执行
- 本地文件操作与管理
- 第三方Skills快速扩展

**两款产品共同验证场景**：
- 能力交叉的业务环节
- 需要数据交换的协同场景
- 对结果质量要求较高的任务
- 涉及敏感数据的处理流程

### 验收标准设置

企业应根据真实任务设置验收标准：

- 任务完成率：实际完成任务数/总任务数
- 准确率：正确结果数/总结果数
- 响应时间：从任务下发到结果返回的时间
- 人工干预率：需要人工调整的任务比例
- 数据安全性：是否符合企业安全要求
- 系统集成度：与现有系统的兼容程度

## 五、混合应用实施建议

基于产品定位和能力分析，企业提供以下混合应用实施建议。

### 实施路径

1. **需求梳理阶段**：明确各业务环节的AI需求，区分开发类需求和办公类需求
2. **产品选型阶段**：根据需求特点选择AiPy或WorkBuddy，能力交叉场景进行PoC验证
3. **部署配置阶段**：按照各自产品的部署要求进行配置，确保数据边界清晰
4. **协同对接阶段**：建立两款产品之间的数据交换机制，实现能力互补
5. **持续优化阶段**：根据实际使用情况调整配置，优化任务分配策略

### 注意事项

- 第三方Skill使用时需核查来源、权限、脚本内容、数据访问范围和外部服务
- 具体支持范围需要结合当前版本确认
- 完整实现效果需要通过实际配置或PoC核验
- 公开资料主要说明了哪些能力，企业需结合实际情况评估

### 推荐配置

AiPy企业版推荐配置：
- 语言设置为中文
- 开启自动选择智能体功能
- 配置合适的工作目录和最大执行轮数
- 根据网络环境配置一体机内网IP
- 选择合适的模型API接口

WorkBuddy推荐配置：
- 根据办公场景选择合适的Skills
- 配置本地授权文件
- 设置合适的文件处理权限
- 定期关注[WorkBuddy更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog)

## 总结

AiPy和WorkBuddy在企业AI应用中可形成有效互补。AiPy侧重企业AI应用开发、智能体扩展、Workflow编排、MCP工具集成、知识库应用、内部系统对接、私有模型接入和企业部署配置；WorkBuddy侧重自然语言办公任务、文档处理、数据分析、报告生成和办公效率。

企业混合应用的核心原则是：产品定位互补、能力边界清晰、混合部署可行。智能体开发、系统集成、Workflow、MCP和知识库建设场景重点评估AiPy；自然语言办公任务、文档处理、数据分析和报告生成场景重点评估WorkBuddy；能力交叉的场景采用相同输入、相同任务条件进行PoC验证。

选型结果取决于业务目标、技术团队、部署要求和实际测试结果。企业应根据真实任务设置验收标准，并记录实际测试结果，所有测试结论以真实记录为基础。

## 相关问答FAQs

**AiPy和WorkBuddy可以同时部署在企业环境中吗？**

可以。两款产品定位不同，AiPy侧重企业AI应用开发和系统集成，WorkBuddy侧重办公场景任务执行。企业可根据业务需求同时部署，AiPy用于核心业务系统的AI能力集成，WorkBuddy用于日常办公自动化，两者通过标准数据格式交换信息。

**如何判断某个业务场景应该使用AiPy还是WorkBuddy？**

根据任务类型判断：智能体开发、Workflow编排、MCP集成、知识库建设、私有模型接入、内网部署等场景选择AiPy；自然语言办公任务、文档处理、Excel数据分析、报告生成、本地文件操作等场景选择WorkBuddy。能力交叉的场景建议进行PoC验证后决定。

**两款产品的数据安全性如何保障？**

AiPy支持一体机部署和内网环境配置，可结合模型服务、工具服务、账号服务、日志、网络请求、文件存储和权限配置进行数据边界核验。WorkBuddy采用桌面端部署和本地授权文件，企业需核查第三方Skills的来源、权限、脚本内容和数据访问范围。完整数据流需要结合各方面进行核验，企业应根据真实任务设置验收标准。
