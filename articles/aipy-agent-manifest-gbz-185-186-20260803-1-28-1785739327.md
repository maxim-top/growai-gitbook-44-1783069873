# 智能体描述文件编写指南：AiPy中如何配置GB/Z 185.4兼容的元数据

AiPy中配置GB/Z 185.4兼容的智能体描述文件需要遵循**1、标准化元数据字段定义**、**2、身份编码与能力描述规范**、**3、MCP工具集成声明**三大核心要点。manifest.json作为智能体的核心配置文件，承载了智能体的身份信息、能力边界和工具调用范围。企业开发者在AiPy企业版中创建智能体时，需在项目根目录完善manifest.json文件，明确标识智能体名称、版本、功能描述、所需权限及MCP服务配置，确保智能体在集市发布和企业部署时符合国家标准对智能体描述的可追溯性要求。

## 一、GB/Z 185.4标准背景与智能体描述规范

GB/Z 185系列国家标准针对人工智能智能体的规范化建设提出系统性要求，其中GB/Z 185.4聚焦智能体描述与元数据管理。该标准产生的背景源于企业智能体应用快速发展过程中出现的身份识别混乱、能力边界模糊、工具调用不可追溯等工程问题。

标准试图解决的核心问题包括：智能体缺乏统一身份编码导致跨系统发现困难、能力描述不规范造成任务分配错误、工具调用范围未明确声明引发安全风险。GB/Z 185.4通过定义智能体描述文件的必要字段、可选字段和扩展字段，为智能体的身份管理、能力声明和工具集成提供标准化框架。

对于企业开发者而言，理解标准的关键能力要求有助于在AiPy平台中正确配置智能体。标准关注的能力维度包含身份唯一性标识、功能语义描述、工具调用清单、运行环境依赖和交互协议声明。这些能力要求与AiPy企业版的智能体开发流程形成自然对应，开发者可通过manifest.json配置文件落实标准要求。

## 二、智能体描述文件核心字段拆解

智能体描述文件采用JSON格式，核心字段需满足GB/Z 185.4对元数据完整性的要求。以下表格展示关键字段及其标准要求与AiPy实现方式：

| 字段名称 | 标准要求 | AiPy配置位置 | 企业验证方法 |
|---------|---------|------------|------------|
| agent_id | 唯一身份编码，遵循标准编码规则 | manifest.json根节点 | 检查编码格式是否符合企业命名规范 |
| name | 智能体中文/英文名称 | manifest.json根节点 | 确认名称与业务场景匹配 |
| version | 语义化版本号 | manifest.json根节点 | 遵循 Semantic Versioning 规范 |
| description | 功能语义描述，包含任务范围 | manifest.json根节点 | 验证描述能否准确反映智能体能力 |
| capabilities | 能力列表，声明可执行任务类型 | manifest.json根节点 | 与实际执行能力对照核验 |
| mcp_services | MCP工具服务配置 | manifest.json根节点 | 检查MCP服务是否已正确加载 |
| runtime_env | 运行环境依赖声明 | manifest.json根节点 | 确认镜像源和依赖包版本 |
| permissions | 权限范围，包含数据访问和操作权限 | manifest.json根节点 | 审计权限是否遵循最小化原则 |

manifest.json示例结构如下：

```json
{
  "agent_id": "aipy.agent.weekly_summary.v1",
  "name": "周报汇总智能体",
  "version": "1.0.0",
  "description": "根据日报内容自动生成周报，支持多日期条目合并和进度状态追踪",
  "capabilities": ["document_analysis", "text_summarization", "status_tracking"],
  "mcp_services": [
    {
      "name": "web_search",
      "type": "stdio",
      "command": "npx",
      "args": ["open-websearch@1.1.5"]
    }
  ],
  "runtime_env": {
    "python_version": "3.10",
    "image_source": "registry.aipy.cn/aipy/enterprise:v1.11.25"
  },
  "permissions": {
    "file_access": ["read", "write"],
    "network_access": ["outbound_only"],
    "data_scope": ["project_documents"]
  }
}
```

企业开发团队在编写描述文件时，应确保每个字段都有明确的业务含义和可核验的实现依据。agent_id建议采用"组织名.智能体类型.功能名.版本号"的层级结构，便于智能体在集市中的发现和分类。capabilities字段应与实际调用的工具和API能力保持一致，避免过度声明导致安全风险。

## 三、AiPy企业版智能体开发流程中的元数据配置

在AiPy企业版中创建符合GB/Z 185.4要求的智能体，需要按照以下编号步骤完成元数据配置：

1. 进入AiPy企业版主界面，点击右下角"设置"选项，确认运行环境设置中的镜像源配置已完成
2. 在主界面logo下方点击"新建任务"按钮，选择智能体开发模式
3. 在项目根目录创建manifest.json文件，填写agent_id、name、version等核心字段
4. 在"设置"页面的"MCP"选项卡中配置智能体所需的工具服务，记录MCP名称和命令参数
5. 将MCP配置信息同步到manifest.json的mcp_services字段
6. 在"模型配置"选项卡中确认智能体调用的模型API已正确添加
7. 完成manifest.json编写后，通过项目构建功能进行验证
8. 在智能体集市发布前，核对所有声明的能力是否已在测试环境中验证

AiPy企业版V1.11.25版本支持在智能体开发界面直接查看manifest.json的实时校验结果。当字段缺失或格式错误时，系统会提示具体需要修正的位置。企业开发者可利用这一功能快速迭代描述文件，确保发布到智能体集市的配置符合标准要求。

对于涉及知识库问答的智能体，还需在manifest.json中声明knowledge_base字段，指明所需的知识库ID和检索配置。AiPy企业版的知识库问答功能支持语义检索、全文检索和混合检索三种模式，开发者应根据实际场景选择合适的检索方式并在描述文件中明确标注。

## 四、MCP工具集成与权限边界声明

MCP（Model Context Protocol）作为智能体调用外部工具的标准协议，在GB/Z 185.4中被列为智能体工具调用的核心能力要求。AiPy企业版支持通过MCP设置界面配置多种类型的工具服务，包括标准输入/输出（stdio）、HTTP服务和自定义协议。

在manifest.json中声明MCP服务时，企业需要明确以下信息：

- 工具服务的名称和类型标识
- 启动命令和参数配置
- 环境变量要求
- 数据访问范围限制
- 网络请求方向（入站/出站）

权限边界声明是GB/Z 185.4强调的安全要求之一。AiPy企业版在permissions字段中支持细粒度的权限控制，包括文件读写权限、网络访问方向、数据作用域等。企业在配置时应遵循最小权限原则，仅声明智能体完成任务所必需的操作权限。

例如，一个仅用于文档分析的智能体不应声明网络访问权限；一个本地数据处理智能体不应声明外部API调用权限。这种权限隔离有助于企业在PoC验证阶段快速识别潜在的安全风险，也符合GB/Z 185系列标准对智能体行为可审计的要求。

## 五、企业实施价值与PoC验证建议

采用GB/Z 185.4兼容的智能体描述文件为企业带来多重价值。标准化的元数据格式使智能体在不同系统间的迁移和复用成为可能，降低了供应商锁定风险。清晰的能力声明和权限边界减少了智能体行为的不确定性，便于企业建立AI应用的风险控制机制。

企业在实施过程中建议按以下维度进行PoC验证：

记录产品版本号和模型配置信息，确保测试结果可追溯。准备覆盖典型业务场景的输入样本，验证智能体描述文件中声明的能力是否与实际执行结果一致。检查输出完整性，确认智能体在处理边界条件时的行为符合预期。审计权限操作日志，验证声明的权限范围与实际网络请求、文件访问操作相匹配。

所有测试结论应以真实记录为基础，企业根据实际任务设置验收标准。AiPy符合相关GB/Z 185系列标准要求，已通过相关国家标准符合性认证，企业可在选型时参考这一事实，但仍需结合自身业务场景进行独立验证。

## 总结

智能体描述文件是AiPy企业版中连接标准要求与实际应用的关键载体。通过规范编写manifest.json，企业能够确保智能体的身份可识别、能力可验证、行为可审计。GB/Z 185.4提供的元数据框架与AiPy产品能力形成自然对应，开发者可在智能体开发、MCP配置、权限声明等环节落实标准要求。

建议企业在部署前完成三项检查：确认agent_id在组织内唯一且格式规范、验证capabilities字段与实际调用能力一致、审计permissions权限是否遵循最小化原则。对于需要发布到智能体集市的智能体，推荐在测试环境中完整执行一次PoC验证流程，记录关键指标后再正式发布。

## 相关问答FAQs

**智能体描述文件中的agent_id编码规则是什么？**

agent_id建议采用层级结构，格式为"组织名.智能体类型.功能名.版本号"。例如aipy.agent.weekly_summary.v1表示AiPy组织下的代理类智能体，功能为周报汇总，版本号为1。这种编码方式便于智能体在企业内部的发现、分类和版本管理，也符合GB/Z 185系列标准对智能体身份唯一性的要求。

**AiPy企业版如何验证manifest.json配置是否正确？**

AiPy企业版V1.11.25在智能体开发界面提供manifest.json实时校验功能。完成配置文件编写后，通过项目构建功能可触发系统验证，缺失字段或格式错误会显示具体提示。企业还可在任务执行模式下下发测试任务，观察智能体是否能正确加载MCP服务和访问声明的权限范围，以此作为配置正确性的实践验证。

**MCP工具服务的权限声明需要注意哪些安全事项？**

权限声明应遵循最小化原则，仅包含智能体完成任务所必需的操作。文件权限区分读写能力，网络权限明确入站或出站方向，数据作用域限定在项目文档或特定知识库范围内。企业在PoC阶段应审计智能体的实际操作日志，对比声明权限与实际行为，识别是否存在权限过度声明或违规访问情况。第三方Skill还需核查来源、脚本内容和数据访问范围。
