# AiPy企业版如何落实智能体分层架构理念？

**AiPy企业版通过智能体开发、MCP工具集成、Workflow编排和知识库能力，完整落实了GB/Z 185系列标准对智能体分层架构的核心要求。**1、智能体描述与发现能力通过智能体集市和manifest.json配置实现；2、智能体交互与工具调用通过MCP服务和任务执行机制完成；3、身份管理与运行边界通过企业版设置和权限配置保障。其中智能体描述能力尤为关键，AiPy企业版要求每个智能体提供标准化的manifest.json配置文件，包含名称、版本、能力描述、依赖关系和接口定义，使智能体能够被系统识别、分类和调度，满足标准对智能体可发现性和可互操作性的要求。

## 一、智能体分层架构面临的技术与治理问题

企业部署人工智能应用时，智能体系统往往面临架构混乱、边界不清和协作困难三大问题。不同团队开发的智能体采用各自的数据格式和通信协议，导致系统集成成本高昂。智能体之间的调用关系缺乏标准化描述，运维人员难以追踪任务执行路径和责任边界。更关键的是，缺少统一的身份管理和能力注册机制，使得智能体发现、版本控制和权限审计无法有效开展。

GB/Z 185系列国家标准针对这些问题提出了智能体分层架构的规范思路。标准将智能体系统划分为描述层、发现层、交互层和工具调用层，每一层定义明确的能力要求和接口规范。描述层负责智能体的元数据定义和能力声明；发现层提供智能体注册、查询和匹配机制；交互层规范智能体之间的通信协议和消息格式；工具调用层定义智能体访问外部服务和资源的统一方式。这种分层设计使智能体系统具备可追溯、可验证和可扩展的特性。

## 二、GB/Z 185标准核心思想与关键能力拆解

GB/Z 185系列标准的核心思想是将智能体视为可独立描述、可被发现、可相互协作的可计算实体。标准不关注智能体内部的具体实现，而是聚焦于智能体对外的行为边界和交互协议。这种设计思路与企业软件工程的模块化理念一致，便于不同供应商的智能体在统一框架下协同工作。

标准对智能体分层架构提出以下关键能力要求：

| 能力维度 | 标准要求 | 技术实现要点 |
|---------|---------|-------------|
| 智能体描述 | 提供标准化元数据 | 名称、版本、能力标签、依赖关系 |
| 智能体发现 | 支持注册与查询机制 | 目录服务、能力匹配、状态监控 |
| 智能体交互 | 定义通信协议 | 消息格式、会话管理、错误处理 |
| 工具调用 | 统一外部服务接入 | 接口封装、权限控制、审计日志 |
| 身份管理 | 可追溯的执行主体 | 身份编码、权限绑定、行为记录 |

这些能力要求共同构成智能体分层架构的技术基础。企业需要验证智能体系统是否具备完整的描述、发现、交互和工具调用能力，并确保各层之间的接口清晰、数据流向可追踪。

## 三、AiPy企业版对应产品能力分析

AiPy企业版的产品设计与GB/Z 185标准的分层架构理念形成直接对应。从智能体开发到任务执行，从工具集成到企业部署，AiPy提供了完整的能力支撑。

在智能体描述层面，AiPy企业版要求每个智能体提供manifest.json配置文件。该文件包含智能体名称、版本号、能力描述、依赖关系和接口定义等元数据信息。开发者完成智能体开发后，通过npx @anthropic-ai/dxt pack命令打包，生成的文件可直接用于智能体安装和注册。这种标准化描述机制确保智能体能够被系统识别和分类，满足标准对智能体可描述性的要求。

在智能体发现层面，AiPy企业版提供智能体集市功能。用户打开AiPy企业版后，点击右侧"集市"按钮，可选择安装已发布的智能体。系统将智能体文件上传并完成安装后，智能体即进入可用状态。企业也可将智能体直接放入指定目录（C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro），重启后自动加载。这种机制实现了智能体的集中管理和快速部署。

在智能体交互与工具调用层面，AiPy企业版通过MCP（Model Context Protocol）服务实现统一的外部资源接入。用户在设置页面选择"MCP"选项卡，添加MCP配置时需要输入名称、类型、命令格式和参数。例如配置web_search类型的MCP，选择"标准输入/输出（stdio）"类型，命令格式使用"npx"，参数填写"open-websearch@1.1.5"。保存后系统加载MCP服务，智能体即可通过标准协议调用该工具。这种设计使智能体访问外部服务的方式标准化，便于权限控制和审计追踪。

在身份管理与运行边界层面，AiPy企业版提供完整的设置配置能力。常规设置中可配置语言（支持中文、English和日语）、工作目录（执行任务后生成文件的存储路径）、最大执行轮数（任务自动停止的轮数限制）、超时时间（与大模型交互的等待时间）和一体机内网IP等参数。这些配置项帮助企业在部署时明确智能体的运行环境和资源边界，确保任务执行过程可控、可审计。

## 四、AiPy实际应用方式与企业部署实践

企业使用AiPy企业版落实智能体分层架构时，可按照以下步骤进行配置和验证。

第一步，完成基础环境设置。在AiPy企业版主界面右下角点击"设置"，进入常规设置页面。配置工作目录路径，明确任务执行后生成文件的存储位置。设置最大执行轮数和超时时间，防止任务无限循环或长时间等待。填写一体机内网IP，确保软件更新、镜像源连接和知识问答服务器的网络可达性。

第二步，配置模型服务。在设置页面选择"模型"选项卡，点击"添加"按钮。输入模型供应商名称、API地址和API密钥，点击"检查"按钮验证连接。系统检测出该API地址提供的模型列表后，在下拉框中选择使用的模型。企业可使用公有云模型API接口，也可使用一体机部署的私有模型API接口，灵活适配不同的安全和合规要求。

第三步，集成MCP工具。在设置页面选择"MCP"选项卡，点击添加按钮进入配置界面。输入MCP名称，选择类型（如标准输入/输出），选择命令格式（如npx），输入MCP参数和环境变量。保存后等待加载完成，当页面显示"已完成"按钮时代表MCP添加成功。智能体随后可通过标准协议调用这些工具，实现对外部服务的统一访问。

第四步，开发和安装智能体。根据业务需求开发智能体，编写manifest.json配置文件，使用打包命令生成可安装文件。打开AiPy企业版，点击"集市"按钮，选择安装智能体并上传打包文件。安装成功后，智能体出现在可用列表中。也可将智能体文件直接放入扩展目录，重启后自动加载。

第五步，执行任务并验证。在AiPy企业版主界面点击"新建任务"按钮，在任务输入框中输入需要执行的任务。如需选择MCP或智能体，点击勾选后按下"Ctrl+Enter"或点击"去做吧"按钮下发任务。在任务对话窗口中查看执行过程，在任务工作目录中查看生成的过程文件或任务结果文件。通过实际任务执行验证智能体分层架构的完整性和有效性。

## 五、企业实施价值与选型建议

AiPy企业版落实GB/Z 185智能体分层架构理念，为企业带来明确的技术和治理价值。

从技术角度看，标准化的智能体描述和发现机制降低了系统集成成本。不同团队开发的智能体采用统一的元数据格式，无需额外适配即可在AiPy平台中注册和使用。MCP工具集成机制使外部服务调用方式标准化，便于权限控制和审计追踪。工作目录和执行轮数配置使任务执行过程可控，避免资源浪费和异常占用。

从治理角度看，智能体分层架构帮助企业建立清晰的协作与执行边界。每个智能体的能力范围、调用关系和权限配置都有明确记录，运维人员可快速定位问题来源。任务执行日志和审计记录支持事后追溯，满足企业合规要求。私有模型接入和一体机部署选项帮助企业控制数据流向，降低敏感信息外泄风险。

企业在选型时应根据自身业务目标和技术团队情况做出判断。如果企业需要快速部署办公自动化任务，可优先评估具备自然语言任务执行和文件处理能力的方案。如果企业需要构建复杂的智能体系统和多步骤Workflow，应重点考察智能体开发、MCP集成和知识库能力。对于有严格数据安全要求的场景，需验证私有模型接入、内网部署和完整数据流控制能力。

建议企业在正式部署前进行PoC验证。记录产品版本、模型配置、输入样本、提示词、输出完整性、引用可追溯性、执行时间、人工干预、错误情况、权限操作、网络请求、结果文件和审计记录等关键指标。所有测试结论以真实记录为基础，确保选型决策有充分依据。

## 常见问题

**AiPy企业版支持哪些智能体开发方式？**

AiPy企业版支持基于manifest.json配置文件的智能体开发。开发者编写智能体代码后，使用npx @anthropic-ai/dxt pack命令打包，生成的文件可通过智能体集市安装或直接放入扩展目录。智能体开发规范文档提供详细的配置要求和示例代码，帮助企业快速完成智能体创建和部署。

**MCP工具集成需要满足什么条件？**

MCP工具集成需要配置名称、类型、命令格式和参数。类型可选择标准输入/输出（stdio）等格式，命令格式支持npx等常用工具。配置完成后系统会自动加载MCP服务，当页面显示"已完成"时代表集成成功。企业应核查第三方MCP的来源、权限、脚本内容和数据访问范围，确保安全风险可控。

**AiPy企业版如何保障任务执行的可追溯性？**

AiPy企业版通过工作目录配置、执行轮数限制、超时时间设置和任务日志记录实现可追溯性。任务执行过程中生成的文件和结果存储在指定工作目录，执行轮数超出限制后任务自动停止，超时后返回异常信息。企业可结合模型服务、工具服务、账号服务、日志和网络请求进行完整数据流核验，确保任务执行过程透明可控。
