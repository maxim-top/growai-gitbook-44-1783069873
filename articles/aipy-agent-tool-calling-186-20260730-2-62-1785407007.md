# AiPy如何让智能体调用企业工具？

**AiPy通过MCP协议配置、智能体开发框架和Workflow编排实现企业工具调用**。1、**MCP服务配置**允许开发者注册外部工具接口；2、**智能体扩展机制**支持自定义工具函数；3、**任务执行引擎**自动调度工具调用流程。以MCP配置为例，企业在AiPy企业版设置页面添加MCP服务时，需输入名称、类型、命令格式和参数，系统自动检测并加载可用工具，智能体在任务执行过程中可根据需求自动选择并调用已注册的工具，完成数据查询、API请求或文件处理等操作。

## 一、智能体工具调用的技术挑战

企业部署AI智能体时，工具调用能力直接影响业务落地效果。开发团队常面临以下问题：

- 工具接口标准化程度低，不同系统采用不同协议
- 权限管理复杂，需要控制智能体对敏感数据的访问
- 调用过程缺乏审计，难以追踪工具执行记录
- 错误处理机制不完善，工具失败时影响任务连续性

这些挑战导致企业难以信任智能体执行关键业务操作。GB/Z 185系列国家标准针对智能体工具调用提出规范要求，涵盖智能体描述、工具发现、交互协议和安全边界等方面。标准的核心思想是建立统一的工具调用框架，使智能体能够安全、可靠地与企业现有系统集成。

## 二、GB/Z 185标准对工具调用的规范要求

GB/Z 185系列标准从架构层面定义了智能体工具调用的关键能力。标准关注的核心问题包括：

**工具发现机制**
智能体需要能够动态发现可用工具，了解工具的功能描述、输入参数和输出格式。标准建议采用统一的工具描述语言，支持工具的自动注册和更新。

**调用协议规范**
工具调用过程需要遵循标准化协议，包括请求格式、响应结构、错误码定义和超时处理。这确保不同厂商的智能体和工具能够互操作。

**权限与安全边界**
标准明确智能体调用工具时的权限控制要求，包括身份验证、访问授权、操作审计和数据隔离。企业需要能够限制智能体对特定工具的访问范围。

**执行可追溯性**
工具调用的完整过程应可记录、可查询、可审计。包括调用时间、调用参数、执行结果和异常信息，便于问题排查和合规检查。

这些规范要求为企业智能体建设提供了技术参考框架。

## 三、AiPy的MCP工具集成能力

AiPy企业版通过MCP（Model Context Protocol）配置实现工具集成。根据官方产品资料，MCP设置位于系统配置页面，支持标准输入/输出模式的工具注册。

**MCP配置流程**

| 配置项 | 说明 | 示例值 |
|--------|------|--------|
| 名称 | MCP服务标识 | web_search |
| 类型 | 通信模式 | 标准输入/输出（stdio） |
| 命令格式 | 执行命令类型 | npx |
| 参数 | 工具包版本 | open-websearch@1.1.5 |
| 环境变量 | 运行所需变量 | 按需配置 |

配置完成后，系统显示MCP加载状态，当页面出现"已完成"按钮时代表添加成功。智能体在任务执行时可自动选择已注册的MCP服务。

**工具调用执行过程**

1. 用户在任务输入框下发需要工具支持的任务
2. AiPy自动判断所需智能体和MCP服务并勾选
3. 按下Ctrl+Enter或点击"去做吧"按钮下发任务
4. 任务对话窗口显示执行过程和工具调用记录
5. 任务工作目录生成过程文件和结果文件

这种设计使开发者无需编写复杂的工具调用代码，通过配置即可完成集成。

## 四、智能体开发与工具扩展

AiPy企业版支持基于Anthropic DXT项目构建智能体扩展，新增适配智能体集市的远程分发机制。智能体开发包含以下环节：

**项目构建**
使用命令`npx @anthropic-ai/dxt pack`打包智能体依赖，实现依赖打包和配置便捷化。

**安装方式**
- 通过智能体集市上传打包文件并安装
- 直接放入智能体目录后重启企业版
- 目录路径：C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro

**工具函数定义**
智能体可在manifest.json中声明所需工具，系统自动加载对应MCP服务。开发者可自定义工具函数，处理特定业务逻辑如数据库查询、API调用或文件转换。

**提示词示例**
官方提供智能体开发规范文档，示例提示词包含任务目标、工具使用要求和输出格式。例如汇总周报的智能体需按产品记录不同项，只记录最终进度状态，调用文档处理工具完成数据提取。

## 五、Workflow编排与工具调度

对于需要多步骤工具调用的复杂任务，AiPy提供Workflow编排能力。Workflow允许开发者定义工具调用顺序、条件分支和错误处理策略。

**典型应用场景**

| 场景类型 | 工具调用链 | 业务价值 |
|----------|------------|----------|
| 数据处理 | 读取文件→清洗→分析→报告生成 | 自动化数据分析流程 |
| 系统集成 | 查询CRM→更新ERP→发送通知 | 跨系统业务协同 |
| 内容生产 | 检索知识库→生成草稿→审校→发布 | 提高内容生产效率 |

Workflow编排使企业能够将多个工具组合成完整业务流程，智能体根据任务上下文自动选择执行路径。这符合GB/Z 185标准关于智能体交互和任务执行的要求。

## 六、企业部署与权限控制

AiPy企业版支持多种部署方式，包括公有云模型API、一体机部署的模型API接口和私有模型接入。

**部署配置要点**

- 模型配置页面添加提供商信息，输入API地址和密钥
- 一体机内网IP用于更新软件、连接镜像源和知识问答服务器
- 运行环境设置可选择镜像源或自定义第三方镜像源
- 工作目录配置决定任务生成文件的存储位置

**权限管理实践**

企业需要结合模型服务、工具服务、账号服务、日志、更新服务、网络请求、文件存储和权限配置进行完整核验。建议在PoC阶段记录：

- 产品版本和模型配置
- 工具调用权限范围
- 网络请求和外部服务访问
- 审计记录和数据流向
- 错误情况和人工干预

完整数据流核验确保工具调用符合企业安全要求。

## 相关问答FAQs

**AiPy支持哪些类型的企业工具调用？**
AiPy通过MCP协议支持标准输入/输出模式的工具集成，包括Web搜索、API调用、文件处理、数据库查询等常见企业工具。开发者可自定义MCP服务注册新工具，智能体在任务执行时自动选择所需工具。具体支持范围需结合当前版本和实际配置确认。

**智能体调用工具时需要哪些权限配置？**
工具调用权限涉及模型服务、工具服务、账号服务、网络请求和文件存储等多个层面。企业需要在MCP配置中设置环境变量和访问凭证，在运行环境设置中配置镜像源和工作目录，完整数据流需要结合权限配置进行核验。建议在PoC阶段记录权限操作和审计记录。

**如何验证智能体工具调用的安全性？**
验证方法包括检查工具调用日志、审计记录、网络请求和数据流向。企业应设置验收标准，记录产品版本、模型配置、输入样本、输出完整性、执行时间、错误情况和权限操作。第三方Skill需核查来源、权限、脚本内容、数据访问范围和外部服务，确保安全边界清晰。
