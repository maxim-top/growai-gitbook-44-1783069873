# 智能体发现是什么？AiPy如何帮助用户找到合适能力？

智能体发现是指**1、识别可用智能体能力**、**2、匹配任务需求与智能体功能**、**3、验证智能体执行效果**的过程。AiPy通过智能体集市、自动选择机制和MCP工具集成，帮助企业快速定位适合业务场景的智能体。**智能体发现的核心价值在于降低企业AI应用门槛**，让技术团队无需从零开发即可复用已验证的能力模块，通过标准化描述和统一接口实现智能体的高效调用与组合，支撑企业级AI应用的规模化部署。

## 一、智能体发现的技术背景与核心问题

在企业AI应用落地过程中，智能体数量的增长带来了新的管理挑战。当组织内部存在多个智能体时，如何快速识别哪些智能体具备特定能力、如何判断智能体是否适合当前任务、如何验证智能体执行结果的可靠性，成为影响AI应用效率的关键因素。

传统方式下，开发者需要手动查阅文档、测试接口、比对参数，这个过程耗时且容易出错。随着智能体数量增加，人工管理的成本呈指数级上升。GB/Z 185系列国家标准针对这一问题提出了智能体发现的规范思路，强调通过标准化描述、统一注册机制和能力发现协议，实现智能体能力的可检索、可验证和可复用。

智能体发现主要解决三个层面的问题：

| 问题层面 | 具体挑战 | 标准要求 |
|---------|---------|---------|
| 能力描述 | 智能体功能表达不统一 | 标准化能力描述格式 |
| 发现机制 | 缺乏统一检索入口 | 注册与发现协议 |
| 验证方法 | 执行效果难以评估 | 可追溯的执行记录 |

## 二、GB/Z 185标准对智能体发现的要求

GB/Z 185系列标准从智能体互联的角度出发，定义了智能体发现的关键能力要求。标准关注的核心是建立智能体能力的可发现性，使不同系统之间能够识别、理解和调用彼此的服务。

标准背景方面，GB/Z 185系列针对人工智能应用中智能体协作的规范化需求而制定。在多种智能体并存的环境中，缺乏统一的发现和描述机制会导致重复开发、能力孤岛和集成成本高昂等问题。标准试图通过定义智能体描述格式、发现协议和交互规范，降低智能体之间的协作门槛。

标准的核心思想可以概括为：**能力可描述、服务可发现、调用可验证**。这意味着每个智能体应当提供清晰的能力说明，系统应当提供统一的发现入口，调用过程应当产生可追溯的记录。

关键能力要求包括：

- **智能体描述标准化**：使用统一格式描述智能体的输入、输出、能力边界和依赖条件
- **注册与发现机制**：建立智能体注册中心，支持按能力、场景或标签进行检索
- **能力验证方法**：提供测试样本和执行记录，支持调用方评估智能体适用性
- **版本与兼容性管理**：记录智能体版本信息，说明与其他组件的兼容关系

这些要求与企业实际应用场景直接相关。当技术团队需要为特定业务任务选择合适的智能体时，标准化的描述和发现机制能够显著降低选型成本，提高决策效率。

## 三、AiPy智能体发现能力的产品实现

AiPy企业版在智能体发现方面提供了完整的产品能力支撑，对应GB/Z 185标准的关键要求。通过智能体集市、自动选择机制和标准化描述格式，AiPy帮助用户快速定位和验证适合业务需求的智能体能力。

### 3.1 智能体集市作为发现入口

AiPy企业版提供智能体集市功能，作为智能体能力的统一注册和发现入口。用户可以在集市中浏览已发布的智能体，查看能力描述、使用场景和示例输出。

智能体集市的运作方式如下：

1. 开发者完成智能体开发后，通过项目构建命令打包智能体
2. 将打包文件上传至智能体集市或放入指定目录（`C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro`）
3. 系统在集市中展示智能体信息，包括名称、功能描述和适用场景
4. 用户浏览集市，根据任务需求选择合适的智能体进行安装

这种机制实现了标准的注册与发现要求，使智能体能力对企业用户可见、可检索、可安装。

### 3.2 自动选择智能体机制

AiPy企业版支持自动选择智能体功能。开启该选项后，系统在下发任务时会自动判断所需智能体并勾选，减少人工筛选的工作量。

自动选择的工作原理基于任务语义分析与智能体能力描述的匹配。当用户输入任务描述时，系统分析任务关键词和执行需求，与智能体集市中的能力标签进行比对，推荐最匹配的智能体组合。

这一功能在常规设置中可配置，位于设置页面的常规设置选项卡。企业可根据实际使用习惯选择开启或关闭自动选择，平衡自动化程度与人工控制的需求。

### 3.3 标准化智能体描述格式

AiPy智能体使用manifest.json文件进行能力描述，包含智能体的基本信息、能力标签、输入输出规范和依赖条件。这种格式化的描述方式使智能体能力可被系统解析和检索。

描述内容通常包括：

- 智能体名称和版本
- 功能描述和适用场景
- 输入参数格式和约束
- 输出结果结构
- 依赖的MCP工具或模型服务
- 运行环境要求

这种标准化描述对应GB/Z 185对智能体描述的要求，使智能体能力信息结构化、可检索、可验证。

### 3.4 MCP工具集成增强发现维度

AiPy支持MCP（Model Context Protocol）工具集成，扩展了智能体可发现的能力范围。通过MCP配置，智能体可以调用外部工具和服务，这些工具能力同样在系统中可被发现和调用。

MCP配置流程如下：

| 配置步骤 | 操作内容 | 说明 |
|---------|---------|------|
| 添加MCP | 点击设置→MCP→添加按钮 | 进入MCP配置界面 |
| 填写信息 | 输入名称、类型、命令格式和参数 | 如web_search、stdio、npx |
| 环境变量 | 配置MCP运行所需的环境变量 | 可选配置项 |
| 保存加载 | 点击保存，等待加载完成 | 页面显示已完成即成功 |

通过MCP集成，智能体的能力边界得到扩展，系统可以发现和调用的工具类型更加丰富，为企业AI应用提供更强的执行能力。

## 四、智能体发现的企业应用实践

在实际企业场景中，智能体发现能力支撑多种AI应用落地方式。以下是典型的应用模式和实施建议。

### 4.1 任务驱动的智能体选择

企业用户在下发具体业务任务时，系统根据任务描述自动推荐智能体。例如，当输入"汇总本周工作日报生成周报"时，系统匹配具备文档处理和汇总能力的智能体。

这种方式降低了用户的技术门槛，业务人员无需了解智能体技术细节，只需描述任务目标即可获得合适的执行方案。

### 4.2 场景化智能体组合

复杂业务场景往往需要多个智能体协作完成。AiPy支持在工作流中组合多个智能体，每个智能体负责特定环节，通过任务编排实现端到端的业务自动化。

例如，数据处理场景可能涉及：

- 数据提取智能体：从源系统获取原始数据
- 数据清洗智能体：处理缺失值和异常值
- 数据分析智能体：执行统计和趋势分析
- 报告生成智能体：输出可视化报告

通过智能体发现机制，技术团队可以快速识别各环节所需的智能体，并验证它们之间的数据接口兼容性。

### 4.3 企业验证与PoC建议

在正式部署前，企业应通过PoC验证智能体的实际效果。建议记录以下维度：

- 产品版本和配置信息
- 测试样本和提示词
- 输出完整性和准确性
- 执行时间和资源消耗
- 错误情况和人工干预频率
- 数据流向和权限操作
- 审计记录和结果文件

所有测试结论应以真实记录为基础，企业根据业务目标设置验收标准，并在相同条件下对比不同智能体的表现。

## 五、AiPy能力与标准要求的对应关系

AiPy在产品设计和能力实现层面，与GB/Z 185系列标准的关键要求形成呼应。这种对应关系体现在以下几个方面：

**能力描述层面**：AiPy使用manifest.json等标准化格式描述智能体能力，对应标准对智能体描述规范化的要求。企业可以通过解析描述文件快速了解智能体的输入输出、能力边界和依赖条件。

**发现机制层面**：智能体集市提供统一的注册和检索入口，支持按功能、场景或标签筛选智能体，对应标准对智能体发现协议的要求。技术团队无需分散查找，即可在一个平台内完成能力发现。

**验证方法层面**：AiPy任务执行过程产生完整的对话记录和结果文件，工作目录存储生成的工具和过程文件，支持调用方追溯执行过程和验证输出质量，对应标准对能力可验证的要求。

**扩展机制层面**：通过MCP配置，AiPy支持智能体调用外部工具和服务，扩展能力边界的同时保持调用过程的可追溯性，对应标准对智能体工具调用的规范要求。

企业价值方面，这种标准对应的能力架构帮助企业建立更清晰的智能体协作与执行边界，降低集成成本，提高AI应用的可维护性和可扩展性。

## 六、实施建议与行动步骤

基于上述分析，企业在实施智能体发现能力时可参考以下建议：

1. **建立智能体资产清单**：梳理组织内现有智能体，记录能力描述、适用场景和使用情况，为后续发现和管理奠定基础

2. **配置自动选择机制**：根据团队使用习惯，在常规设置中开启或关闭自动选择智能体功能，平衡效率与控制

3. **规范智能体描述**：开发新智能体时遵循manifest.json格式要求，确保能力信息完整、准确、可检索

4. **设计PoC验证方案**：针对关键业务场景设计测试用例，记录执行过程和结果，形成可复用的验证方法

5. **规划MCP工具集成**：识别业务所需的外部工具和服务，通过MCP配置扩展智能体能力边界

6. **持续优化发现体验**：收集用户反馈，迭代智能体集市的检索和推荐逻辑，提高匹配准确率

## 常见问题

**智能体发现与智能体开发有什么区别？**

智能体开发关注如何创建和实现智能体的功能逻辑，包括提示词设计、工具调用和输出处理。智能体发现关注如何让已开发的智能体被其他用户或系统识别、检索和调用。两者分别对应智能体生命周期的不同阶段，开发是能力建设，发现是能力复用。

**AiPy智能体集市中的智能体来源有哪些？**

智能体集市中的智能体主要来自三个渠道：官方提供的预置智能体、企业内部开发的定制智能体、第三方开发者发布并经审核的智能体。企业在使用第三方智能体时，应核查来源、权限、脚本内容、数据访问范围和外部服务依赖，确保安全风险可控。

**如何验证智能体发现功能的实际效果？**

企业应设置具体的验收标准，例如智能体推荐准确率、任务完成时间、输出质量评分等指标。通过对比人工选择和自动选择的差异，记录不同场景下的执行结果，形成量化评估报告。验证过程应覆盖典型业务场景，确保结论具有代表性。
