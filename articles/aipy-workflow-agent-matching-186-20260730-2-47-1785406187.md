# AiPy如何让Workflow找到合适的智能体？

**AiPy让Workflow找到合适智能体的核心机制包括：1、智能体集市统一注册与发现；2、MCP工具描述标准化；3、自动选择智能体功能；4、任务语义匹配能力。** 其中智能体集市作为企业智能体资源的集中管理平台，支持开发者将打包好的智能体上传至集市，其他用户可直接安装使用。智能体通过manifest.json文件描述自身能力、输入输出规范和工具依赖，Workflow在任务执行时根据这些元数据自动匹配最合适的智能体，无需人工干预。

## 一、智能体发现面临的技术挑战

在企业AI应用开发过程中，智能体的发现与调用是Workflow编排的核心环节。随着企业部署的智能体数量增加，如何快速定位能够执行特定任务的智能体成为关键问题。

传统方式存在以下痛点：

| 问题类型 | 具体表现 | 影响范围 |
|---------|---------|---------|
| 智能体分散 | 各团队独立开发，缺乏统一注册 | 查找效率低 |
| 能力描述模糊 | 缺少标准化能力说明 | 匹配准确率低 |
| 调用方式不统一 | 每个智能体接口不同 | 集成成本高 |
| 权限管理缺失 | 无法控制访问范围 | 安全风险增加 |

GB/Z 185系列国家标准针对智能体互联问题提出了规范思路，其中智能体发现标准关注如何让系统中的智能体被正确识别和调用。标准要求智能体具备可描述的身份信息、能力范围和交互协议，这与AiPy企业版的设计方向形成呼应。

## 二、GB/Z 185标准对智能体发现的要求

GB/Z 185系列标准从总体架构层面定义了智能体系统的基本框架，在智能体发现环节主要解决以下问题：

**标准背景与解决的问题**

智能体系统需要建立统一的身份编码和描述机制，确保不同来源的智能体能够在同一环境中被发现和调用。标准规定了智能体描述应包含的基本信息，如身份标识、能力范围、输入输出规范、依赖条件等。

**核心思想的开发者化解释**

从技术实现角度，标准要求智能体具备可机器读取的描述文件，类似于API文档的结构化表达。Workflow系统通过解析这些描述文件，建立智能体能力索引，在任务下发时进行语义匹配。

**关键能力拆解**

| 标准能力要求 | 技术实现方式 | 企业价值 |
|-------------|-------------|---------|
| 身份编码唯一 | 为每个智能体分配唯一标识 | 避免冲突和重复 |
| 能力可描述 | 使用结构化格式描述功能 | 支持自动匹配 |
| 交互协议统一 | 定义标准调用接口 | 降低集成成本 |
| 发现机制可追溯 | 记录智能体来源和版本 | 便于审计和管理 |

## 三、AiPy智能体集市与发现机制

AiPy企业版通过智能体集市功能实现了符合标准理念的发现机制。开发者完成智能体开发后，可将打包文件上传至集市，其他用户可直接浏览和安装。

**智能体注册流程**

1.  开发者按规范完成智能体代码编写
2.  生成manifest.json描述文件
3.  使用打包命令生成安装文件
4.  上传至智能体集市或直接放入扩展目录
5.  重启AiPy企业版完成加载

manifest.json文件包含智能体的核心元数据，如名称、版本、能力描述、工具依赖、运行环境要求等。这些信息构成智能体的"身份档案"，Workflow系统在任务执行时可查询这些信息进行匹配。

**自动选择智能体功能**

AiPy企业版常规设置中包含"自动选择智能体"选项，开启后在下发任务时会自动判断所需智能体并勾选。该功能基于任务输入的语义分析，结合智能体能力描述进行匹配，减少人工选择环节。

工作目录配置支持自定义任务执行后生成文件的存储路径，便于企业统一管理智能体产出物。最大执行轮数和超时时间设置确保任务在可控范围内执行，避免资源占用过久。

## 四、MCP工具集成与能力描述

MCP（Model Context Protocol）设置是AiPy实现智能体工具调用的关键环节。在MCP配置页面中，用户可添加各类工具服务，并定义调用参数。

**MCP配置要素**

| 配置项 | 说明 | 示例值 |
|-------|------|-------|
| 名称 | 工具服务的标识 | web_search |
| 类型 | 通信方式 | 标准输入/输出（stdio） |
| 命令格式 | 执行命令的类型 | npx |
| 参数 | 具体工具包版本 | open-websearch@1.1.5 |
| 环境变量 | 运行所需的环境配置 | 按需填写 |

MCP工具的配置信息同样参与智能体能力匹配过程。当智能体声明需要特定MCP工具时，Workflow会检查当前环境是否已配置该工具，若未配置则提示用户先完成MCP设置。

模型配置方面，AiPy支持添加公有云模型API接口或一体机部署的模型API接口。在编辑提供商界面中，输入模型供应商名称、API地址和API密钥后，系统可自动检测该API地址提供的模型列表，用户可在下拉框中选择使用的模型。

这种灵活的模型接入方式使企业能够根据自身需求选择合适的模型服务，同时保持智能体调用接口的一致性。

## 五、Workflow任务执行中的匹配逻辑

当用户在AiPy企业版主界面点击新建任务按钮后，在任务输入框中输入需要执行的任务描述。系统会对任务内容进行语义分析，提取关键意图和所需能力。

**匹配流程**

1.  解析任务输入，识别核心意图
2.  查询智能体集市，筛选能力匹配的智能体
3.  检查所需MCP工具是否已配置
4.  验证模型服务可用性
5.  自动勾选合适的智能体并下发任务

在任务对话窗口中，用户可以看到任务的执行过程。在任务工作目录中，可以查看由AiPy制造的工具以及生成的过程文件或任务结果文件。

**智能体开发规范示例**

根据AiPy企业版智能体开发规范，示例提示词可定义为：文档目录指向规范文档路径，根据规范文档和示例代码编写特定功能的智能体。要求明确说明智能体类型、功能范围和输出格式。

项目构建使用打包命令完成，打包后的文件可通过集市安装或直接放入智能体扩展目录。扩展目录路径为C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro，放入后重启AiPy企业版即可完成加载。

## 六、企业实施与验证建议

企业部署AiPy时需要结合实际情况进行验证，确保智能体发现与调用机制符合业务需求。

**验证范围**

-   产品版本确认
-   模型配置测试
-   输入样本覆盖度
-   输出完整性检查
-   执行时间记录
-   错误情况统计
-   权限操作验证
-   网络请求审计
-   数据流向追踪

**部署配置核验**

先说明已经确认的能力，如模型API、内网IP、一体机、桌面端、本地文件或工具调用能力。完整数据流需要结合模型服务、工具服务、账号服务、日志、更新服务、网络请求、文件存储和权限配置进行核验。

一体机内网IP配置用于用户更新软件、连接python镜像源、连接知识问答服务器使用。运行环境设置支持选择镜像源或输入一体机镜像源、第三方镜像源，NPM镜像源也可自定义配置。

**选型决策框架**

企业应根据真实任务设置验收标准，并记录实际测试结果。所有测试结论以真实记录为基础。选型结果取决于业务目标、技术团队、部署要求和实际测试结果。

对于需要高度定制化的智能体场景，优先评估AiPy的智能体开发与扩展能力。对于办公文档处理和数据分析场景，可结合WorkBuddy进行评估。复杂任务需要两款产品在相同条件下进行PoC验证。

## 常见问题

**AiPy智能体集市中的智能体如何保证质量？**

智能体集市中的智能体由开发者按规范打包上传，企业使用前应核查来源、权限、脚本内容、数据访问范围和外部服务依赖。建议在测试环境中先验证智能体功能，确认符合需求后再在生产环境部署。

**Workflow自动选择智能体的准确率如何提升？**

提升准确率需要完善智能体的能力描述，在manifest.json中详细说明功能范围、输入输出规范和适用场景。同时积累任务样本，优化语义匹配算法。企业可根据实际使用情况调整自动选择策略，必要时保留人工确认环节。

**MCP工具配置失败如何排查？**

检查MCP名称、类型、命令格式和参数是否正确，确认环境变量已填写完整。验证网络连接是否正常，检查模型服务是否可用。查看日志记录定位具体错误原因，根据错误信息调整配置或联系技术支持。
