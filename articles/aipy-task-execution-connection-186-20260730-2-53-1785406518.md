# AiPy任务执行如何连接模型、智能体与工具？

AiPy任务执行通过**1、模型API配置**建立与大语言模型的连接通道，**2、智能体开发与管理**实现任务逻辑封装，**3、MCP工具集成**完成外部能力调用。三者形成完整的技术链路，模型提供推理能力，智能体承载业务逻辑，工具扩展执行边界。以模型配置为例，AiPy企业版支持在设置页面添加公有云或私有模型API，输入API地址与密钥后系统自动检测可用模型，任务下发时根据需求自动匹配相应模型完成推理，确保企业数据不出内网的同时保持模型调用灵活性。

## 一、智能体任务执行的技术挑战

企业引入AI智能体时，首要问题是如何让抽象的任务指令转化为可执行的完整流程。开发者面临三层技术难点：模型选择与接入、智能体逻辑封装、外部工具调用。

传统方案中，这三个环节往往由不同系统处理，导致数据流转复杂、权限管理分散、执行过程不可追溯。业务人员下达"汇总本周销售数据并生成报告"这样的自然语言任务时，系统需要完成以下工作：理解任务意图、选择合适模型、调用数据处理工具、执行分析逻辑、生成可视化结果、存储最终文件。

GB/Z 185系列国家标准针对智能体互联问题提出了规范化思路，涵盖总体架构、身份编码、身份管理、智能体描述、智能体发现、智能体交互和智能体工具调用七个维度。标准核心价值在于建立统一的智能体协作框架，使不同来源的智能体能够在同一环境中安全、高效地协同工作。

对企业和开发者而言，理解标准要求并找到对应的产品能力落地方式，是评估智能体平台的关键环节。

## 二、GB/Z 185标准的核心思路

GB/Z 185系列标准针对智能体技术发展中的治理问题提出了解决方案。在标准制定背景中，智能体应用呈现爆发式增长，但缺乏统一的架构规范导致互操作性差、安全风险高、审计追溯困难。

标准主要解决三个问题：**身份可识别**确保每个智能体有唯一标识，**能力可描述**让系统能够理解智能体能做什么，**交互可管控**保障任务执行过程安全可控。

核心思想采用分层架构设计：底层定义智能体身份编码规则，中间层规范能力描述格式，上层建立交互协议和工具调用机制。这种设计使智能体既能独立运行，又能在多智能体环境中协作完成任务。

关键能力要求包括：智能体必须具备明确的身份标识、能力边界清晰、工具调用需经过授权验证、执行过程可记录审计、数据流向可追溯。这些要求与企业级AI应用的安全合规需求高度一致。

## 三、AiPy模型接入与配置能力

AiPy企业版在模型配置层面提供了灵活的接入方案。用户在设置页面选择模型选项卡，点击添加按钮即可配置新模型。系统支持两种部署模式：公有云模型API接口和一体机部署的私有模型API。

配置流程包含四个步骤：
1. 输入模型供应商名称，如"公司私有模型"
2. 填写API地址，如http://192.168.0.10/v1
3. 输入API请求密钥
4. 点击检查按钮，系统自动检测该API地址提供的模型列表

这种设计对应GB/Z 185标准中智能体与外部服务交互的规范要求。模型作为智能体的核心推理引擎，其接入方式直接影响任务执行的安全性和可控性。AiPy通过统一的模型配置界面，使企业能够在内网环境中完成模型服务集成，避免敏感数据流向外部。

模型配置完成后，系统在任务执行时自动选择合适的模型进行处理。用户可在常规设置中开启"自动选择智能体"功能，下发任务时系统根据任务类型自动匹配所需模型和智能体组合。超时时间参数控制AiPy与大模型交互时的等待时长，超过设定时间则判定为异常并终止等待，防止任务长时间挂起占用系统资源。

## 四、智能体开发与任务执行机制

AiPy智能体开发遵循标准化流程，与GB/Z 185智能体描述和身份管理要求形成能力呼应。开发者完成智能体编码后，通过项目构建命令打包生成可扩展文件，上传至智能体集市完成安装。

智能体安装支持两种方式：通过集市界面上传安装包，或直接放入Aipy智能体目录（C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro）后重启企业版。安装成功后，智能体在集市中显示为可用状态，任务执行时可被自动调用。

任务执行流程如下：
1. 在主界面点击新建任务按钮
2. 在任务输入框中输入自然语言指令
3. 根据需要勾选MCP或智能体
4. 按下Ctrl+Enter或点击"去做吧"按钮下发任务
5. 在任务对话窗口查看执行过程
6. 在任务工作目录查看生成的文件或结果

这种设计使业务人员无需了解底层技术细节即可完成复杂任务。智能体承载业务逻辑，将自然语言指令转化为可执行的操作序列，模型提供推理能力，工具扩展执行范围，三者协同完成端到端任务处理。

工作目录设置允许用户自定义执行任务后生成的文件存储路径，便于企业统一管理产出物。最大执行轮数参数控制任务的最大回复轮数，超出限制后任务自动停止，防止无限循环消耗计算资源。

## 五、MCP工具集成与扩展能力

MCP（Model Context Protocol）是AiPy连接外部工具的核心机制，对应GB/Z 185标准中智能体工具调用的规范要求。用户在设置页面选择MCP选项卡，点击添加按钮进入配置界面。

MCP配置包含五个要素：
- 名称：标识工具用途，如"web_search"
- 类型：选择标准输入/输出（stdio）等通信方式
- 命令格式：指定执行命令，如npx
- 参数：输入具体参数，如open-websearch@1.1.5
- 环境变量：配置工具运行所需的环境变量

配置完成后系统显示加载页面，出现"已完成"按钮代表MCP添加成功。此后智能体在执行任务时可调用该工具完成特定操作，如网络搜索、文件处理、数据分析等。

MCP机制的优势在于将工具调用标准化。第三方工具只需遵循MCP规范即可接入AiPy平台，企业可根据业务需求灵活扩展工具链。同时，所有工具调用记录可追溯，满足企业审计和安全合规要求。

对于第三方Skill或工具，建议企业核查来源、权限、脚本内容、数据访问范围和外部服务连接情况，确保工具使用符合内部安全策略。

## 六、企业部署与数据安全边界

AiPy企业版与一体机硬件产品结合，为企业提供一站式AI解决方案。部署配置涉及多个层面：模型服务、账号服务、网络请求、日志记录、文件存储和权限管理。

已确认能力包括：模型API支持内网IP配置、一体机本地部署、桌面端运行、本地文件处理、工具调用权限控制。完整数据流需要企业结合当前版本和实际配置进行核验，确认模型服务、工具服务、账号服务、日志、更新服务、网络请求、文件存储和权限配置的完整链路。

常规设置中"一体机内网IP"参数用于填写一体机服务器的内网IP，用户更新软件、连接python镜像源、连接知识问答服务器均使用该配置。运行环境设置允许用户选择镜像源或输入一体机镜像源、第三方镜像源，NPM镜像源同样支持自定义配置。

自定义配置功能支持修改logo、角色风格和推荐任务，配置文件位于C:\Users\用户名\.aipyapp\aipy-enterprise.yml。企业可根据品牌形象和业务需求进行个性化调整。

语言设置目前支持中文、English和日语三种，风格可在aipy-enterprise.yml文件中配置，发送快捷键可选择Ctrl+Enter或Enter。这些配置项使企业能够根据团队使用习惯优化操作体验。

具体支持范围需要结合当前版本确认，完整实现效果需要通过实际配置或PoC核验。建议企业与AiPy技术团队沟通，获取最新的兼容性信息和部署最佳实践。

## 常见问题

**AiPy支持哪些类型的模型接入？**

AiPy企业版支持公有云模型API接口和一体机部署的私有模型API。用户可在模型配置页面添加模型，输入API地址与密钥后系统自动检测可用模型列表。私有模型部署适合对数据安全要求较高的企业场景。

**MCP工具调用是否安全可控？**

MCP配置需要明确工具名称、类型、命令和参数，所有工具调用记录可追溯。企业可核查第三方工具来源、权限和数据访问范围，确保符合内部安全策略。未授权的工具无法被智能体调用。

**任务执行过程如何审计和追溯？**

AiPy在任务对话窗口显示执行过程，任务工作目录存储生成的文件和结果。企业可结合日志记录、网络请求监控和文件存储权限配置，建立完整的审计链条。关键操作均有记录可供追溯。
