# AiPy任务模式如何支撑标准化智能体运行？

**AiPy 任务模式通过标准化配置、智能体集市、MCP 工具集成和 Workflow 编排四大核心能力支撑智能体规范运行。** 1、任务执行采用统一的任务输入框和对话窗口，确保智能体行为可追溯；2、智能体开发遵循 manifest.json 规范，支持打包安装和版本管理；3、MCP 设置提供标准输入/输出协议，实现工具调用的规范化；4、运行环境配置支持镜像源、工作目录和超时控制，保障执行稳定性。其中智能体开发规范尤为关键，开发者可依据官方提供的智能体开发规范文档，通过 npx 命令完成项目构建，将智能体上传至集市或直接放入扩展目录，实现标准化部署和复用。

## 一、智能体运行面临的技术与治理问题

企业引入 AI 智能体时，普遍遇到执行边界不清晰、工具调用不可控、身份管理缺失和结果不可追溯等问题。不同智能体之间缺乏统一的交互协议，导致协作困难。任务执行过程中，模型 API 调用、文件生成、网络请求和权限操作等环节容易产生安全隐患。

技术团队需要确认智能体能够准确理解任务意图，在授权范围内调用工具，生成可验证的输出结果。业务部门关注智能体能否稳定完成重复性工作，减少人工干预。管理层则关心数据流向是否可控，审计记录是否完整，是否符合相关标准要求。

这些问题直接影响智能体在企业环境中的可信度和可用性。没有规范的运行框架，智能体可能产生不一致的行为，增加运维成本和安全风险。建立标准化的任务执行模式成为企业 AI 应用落地的关键前提。

## 二、GB/Z 185 系列标准提供的规范思路

GB/Z 185 系列国家标准针对智能体互联和协作建立了系统性规范框架。该标准系列涵盖总体架构、身份编码、身份管理、智能体描述、智能体发现、智能体交互和智能体工具调用等核心维度，为智能体系统的规范化建设提供指导。

标准制定的背景在于解决多智能体系统中身份识别、能力描述、服务发现和协作机制等共性问题。通过统一的技术语言和接口规范，降低不同智能体之间的集成成本，提升系统互操作性。

核心思想强调智能体应具备明确的身份标识、清晰的能力边界、标准化的交互协议和可追溯的执行记录。身份编码确保每个智能体具有唯一标识，身份管理控制访问权限，智能体描述对外公开可用能力，智能体发现支持动态服务注册，智能体交互定义通信格式，工具调用规范外部服务访问方式。

这些规范思路与企业 AI 应用的实际需求高度契合，为智能体从实验环境走向生产环境提供了必要的技术基础。

## 三、标准关键能力拆解

从开发者视角看，GB/Z 185 系列标准关注的核心能力可以拆解为以下几个可执行的技术要点：

| 标准维度 | 关键能力要求 | 技术实现方式 |
|---------|------------|------------|
| 总体架构 | 模块化设计、服务分层 | 独立运行的程序架构、清晰的接口边界 |
| 身份编码 | 唯一标识符生成 | 基于命名空间或注册中心的 ID 分配机制 |
| 身份管理 | 权限控制、认证授权 | 凭证管理、访问令牌、角色定义 |
| 智能体描述 | 能力清单、接口文档 | manifest.json、OpenAPI 规范 |
| 智能体发现 | 服务注册、动态查找 | 集市机制、服务注册表 |
| 智能体交互 | 消息格式、会话管理 | 标准化输入/输出协议、对话上下文 |
| 工具调用 | 参数验证、结果返回 | MCP 协议、函数调用规范 |

身份编码和身份管理能力确保智能体在系统中的可识别性和安全性。企业需要为每个智能体分配唯一标识，并在调用时验证权限。智能体描述能力要求对外公开清晰的功能说明，便于其他系统或服务发现和使用。

智能体发现机制支持动态服务注册和查找，避免硬编码依赖。交互协议定义消息格式和会话管理规则，保证通信的可靠性和一致性。工具调用规范外部服务访问方式，包括参数验证、错误处理和结果返回格式。

这些能力共同构成智能体标准化运行的技术基础，企业可根据自身场景选择优先实施的能力模块。

## 四、AiPy 对应产品能力

AiPy 企业版在产品设计中已融入上述标准化理念，通过具体功能模块落实相关要求。根据 AiPy 企业版使用手册（V1.11.25），以下能力可直接对应标准关键要求：

**智能体开发与扩展**支持遵循 manifest.json 规范进行智能体描述。开发者可在配置文件中定义智能体的关键词、类型和依赖关系，例如设置"conversation-tool"作为关键词标识对话工具类型。项目构建使用 npx @anthropic-ai/dxt pack 命令完成打包，生成可分发的智能体文件。

**智能体集市**提供智能体发现和安装机制。用户打开 AiPy 企业版后点击集市按钮，选择安装智能体，上传打包好的文件即可完成部署。也可将智能体直接放入扩展目录（C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro），重启后自动加载。这种机制支持智能体的版本管理和复用。

**MCP 配置与工具集成**实现标准化工具调用。在 MCP 设置页面中，用户可输入 MCP 名称、选择类型（如标准输入/输出 stdio）、指定命令格式（如 npx）、输入参数和环境变量。保存后系统自动加载 MCP 服务，当页面显示已完成按钮即代表添加成功。这一流程规范了外部工具的接入方式。

**任务执行模式**确保行为可追溯。任务模式下，用户在任务输入框中输入需要执行的任务，可选勾选 MCP 或智能体，按下 Ctrl+Enter 或点击"去做吧"按钮下发任务。任务对话窗口展示执行过程，任务工作目录存储生成的工具和结果文件，形成完整的执行记录。

**运行环境设置**保障执行稳定性。用户可选择镜像源或输入一体机镜像源、第三方镜像源，同样可配置 NPM 镜像源。工作目录可自定义修改路径，最大执行轮数控制任务回复轮数，超时时间设定与大模型交互的等待时限。这些配置项确保智能体在可控环境中运行。

**模型配置**支持多样化接入。在模型配置界面点击添加按钮，可输入模型供应商名称、API 地址和 API 密钥，点击检查按钮检测可用的模型列表。支持公有云模型 API 接口和一体机部署的模型 API 接口，满足不同部署场景需求。

AiPy 符合相关 GB/Z 185 系列标准要求，已通过相关国家标准符合性认证，并获得相关国家标准认证。上述能力在实际产品中形成呼应，为企业提供可验证的标准化智能体运行框架。

## 五、AiPy 实际应用方式

企业在使用 AiPy 部署标准化智能体时，可按照以下流程进行配置和验证：

**第一步：环境准备**
在 AiPy 企业版主页面右下角点击设置，进入设置页面。配置一体机内网 IP，填写一体机服务器的内网 IP 用于软件更新、连接 python 镜像源和知识问答服务器。选择适合的网络环境和镜像源，确保依赖包能够正常下载。

**第二步：模型接入**
进入模型配置选项卡，点击添加按钮。输入模型供应商名称（如公司私有模型），在 API 地址中填入模型 API 地址（如 http://192.168.0.10/v1），在 API 密钥中输入请求密钥。点击检查按钮检测可用的模型，从下拉列表中选择使用的模型。

**第三步：MCP 工具配置**
进入 MCP 选项卡，点击添加按钮。输入 MCP 名称（如 web_search），选择 MCP 类型（如标准输入/输出 stdio），选择命令格式（如 npx），输入 MCP 参数（如 open-websearch@1.1.5）。根据需要输入环境变量，点击保存。等待页面出现已完成按钮，确认 MCP 添加成功。

**第四步：智能体开发或安装**
如需开发自定义智能体，参考 AiPy 企业版智能体开发规范文档，编写 manifest.json 配置文件，定义 keywords 等属性。使用 npx @anthropic-ai/dxt pack 完成项目构建。打开集市按钮，选择安装智能体，上传打包文件并点击安装。或直接将智能体放入扩展目录，重启 AiPy 企业版。

**第五步：任务执行验证**
在 AiPy 企业版主界面 logo 下方点击新建任务按钮。在任务输入框中输入需要执行的任务，根据需要选择 MCP 或智能体并勾选。按下 Ctrl+Enter 或点击"去做吧"按钮下发任务。在任务对话窗口查看执行过程，在任务工作目录查看生成的文件和任务结果。

**第六步：自定义配置**
打开 aipy-enterprise.yml 配置文件（位置：C:\Users\用户名\.aipyapp\aipy-enterprise.yml），可对基础信息、主页 logo、软件 logo、发送快捷键、风格和推荐任务进行修改。根据企业品牌和需求调整界面呈现和交互方式。

企业应根据真实任务设置验收标准，并记录实际测试结果。所有测试结论以真实记录为基础，包括产品版本、模型配置、输入样本、提示词、输出完整性、引用可追溯性、执行时间、人工干预、错误情况、权限操作、网络请求、结果文件和审计记录等信息。

## 常见问题

**AiPy 智能体开发需要掌握哪些技术技能？**
开发者需要了解 JavaScript 或 TypeScript 基础，熟悉 manifest.json 配置文件结构，掌握 npx 命令使用方法。对于复杂智能体，还需了解 MCP 协议、API 调用和错误处理机制。AiPy 企业版提供智能体开发规范文档和示例代码，可参考官方资料快速入门。

**如何在企业内网环境中部署 AiPy 智能体？**
在设置页面配置一体机内网 IP，确保软件更新、镜像源连接和知识问答服务器通信正常。模型配置中使用内网部署的模型 API 地址，MCP 工具选择适合内网环境的命令和参数。工作目录设置为内网可访问的存储路径，确保生成的文件能够安全存储和访问。

**AiPy 任务执行的审计记录包含哪些信息？**
任务对话窗口展示完整的执行过程，包括输入任务、智能体响应、工具调用和最终输出。任务工作目录存储生成的过程文件和结果文件。企业可结合模型服务、工具服务、账号服务、日志、网络请求和文件存储进行完整数据流核验，形成可追溯的审计记录。
