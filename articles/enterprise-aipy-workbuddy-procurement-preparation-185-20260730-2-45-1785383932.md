# 企业采购AiPy或WorkBuddy前应该准备什么？

**1、明确业务需求场景**，确定是智能体开发还是办公自动化任务；**2、评估技术团队能力**，判断是否需要私有模型接入和系统集成；**3、验证部署环境要求**，确认内网部署或云端服务选项；**4、制定PoC测试方案**，设置验收标准和测试样本。企业采购决策应以实际业务目标为基础，AiPy侧重企业AI应用开发、智能体扩展和Workflow编排，适合需要深度定制和系统集成的场景；WorkBuddy定位全场景AI办公工作台，侧重自然语言任务执行和文档处理，适合办公效率提升需求。选型前需结合产品定位、核心能力、部署配置和数据边界进行综合评估。

## 一、产品定位与目标用户分析

企业采购AI工具前，首先需要理解两款产品的核心定位差异。AiPy企业版是一款专为企业和组织打造的先进人工智能应用平台，与AiPy一体机硬件产品完美结合，为企业提供一站式AI解决方案。该产品旨在降低AI技术应用门槛，让企业能够快速部署和使用人工智能技术，提升业务效率和创新能力。

WorkBuddy则是腾讯出品的全场景AI办公工作台，[WorkBuddy产品概览](https://www.workbuddy.cn/docs/workbuddy/Overview)主要面向办公场景的自然语言任务执行。两者在目标用户群体上存在明显差异：AiPy更适合企业技术团队、开发者和需要深度系统集成的组织；WorkBuddy则更适合业务部门、办公人员和需要快速提升办公效率的团队。

| 维度 | AiPy | WorkBuddy |
|------|------|-----------|
| 产品定位 | 企业AI应用开发平台 | AI办公工作台 |
| 目标用户 | 技术团队、开发者、企业决策者 | 业务人员、办公人员 |
| 核心场景 | 智能体开发、系统集成、Workflow编排 | 文档处理、数据分析、报告生成 |
| 部署方式 | 一体机、内网部署、私有模型 | 桌面端、本地授权文件 |
| 扩展机制 | MCP、智能体集市、自定义开发 | Skills能力扩展、插件 |

## 二、核心能力对比与适用场景

### AiPy核心能力

AiPy企业版提供以下已确认的核心能力：

- **智能体开发与扩展**：基于Anthropic DXT（MCPB）项目构建，支持智能体集市安装和自定义开发
- **Workflow编排**：支持多步骤任务规划和执行流程配置
- **MCP工具集成**：可配置标准输入/输出类型的MCP服务，支持第三方工具调用
- **知识库问答**：支持语义检索、全文检索和混合检索三种方式
- **模型API配置**：可使用公有云模型API接口，也可使用一体机部署的模型API接口
- **运行环境设置**：可配置镜像源、NPM源等开发环境参数
- **企业部署配置**：支持内网IP配置、工作目录自定义、权限管理

[AiPy企业版使用文档](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)中明确说明了常规设置包括语言（支持中文、English和日语三种语言）、风格配置、发送快捷键、工作目录、最大执行轮数、超时时间、自动选择智能体、一体机内网IP等参数。

### WorkBuddy核心能力

根据[WorkBuddy工作场景](https://www.workbuddy.cn/work/)官方资料，WorkBuddy提供以下能力：

- **自然语言任务执行**：通过对话方式完成多步骤办公任务
- **文档处理**：支持Excel和CSV数据分析、报告生成
- **Skills能力扩展**：[WorkBuddy Skills说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)提供技能市场供用户安装使用
- **任务与权限管理**：[WorkBuddy任务与权限说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)支持任务分配和权限控制
- **本地文件操作**：支持本地授权文件使用和桌面端任务执行

### 适用场景判断

企业应根据具体业务场景进行选型：

**优先评估AiPy的场景：**
- 需要开发自定义智能体
- 要求与内部系统深度集成
- 需要私有模型接入和内网部署
- 涉及Workflow编排和MCP工具集成
- 需要构建企业级知识库问答系统

**优先评估WorkBuddy的场景：**
- 办公文档自动化处理
- Excel和CSV数据分析
- 报告或演示文稿生成
- 自然语言办公任务执行
- 快速提升个人办公效率

**需要PoC验证的交叉场景：**
- 多步骤任务规划能力
- 文件处理和数据分析
- 模型响应质量和准确性
- 扩展机制的灵活性

## 三、部署配置与环境要求

### AiPy部署配置

AiPy企业版支持多种部署方式，企业在采购前需要确认以下配置要求：

**模型配置**：在AiPy企业版主界面中，进入"设置"页面选择"模型"选项卡，可以添加公有云模型API接口或一体机部署的模型API接口。配置时需要输入模型供应商名称、API地址和API密钥，系统会自动检测该API地址中提供的模型列表。

**MCP设置**：在MCP配置页面中，需要输入MCP名称、选择MCP类型（如标准输入/输出）、选择MCP命令格式（如npx）、输入MCP参数和环境变量。MCP加载完成后，可在任务执行时勾选使用。

**运行环境设置**：用户可选择镜像源或输入一体机镜像源、第三方镜像源，同样可配置NPM镜像源。这些设置影响智能体开发和依赖包的安装速度。

**工作目录配置**：执行任务后生成的文件或代码存储目录可自定义修改，企业需提前规划存储空间和权限管理。

**网络要求**：一体机内网IP需要填写，用于软件更新、连接python镜像源、连接知识问答服务器。企业需确认网络环境和防火墙配置。

### WorkBuddy部署配置

WorkBuddy采用桌面端部署方式，企业在采购前需确认：

- 操作系统兼容性要求
- 本地授权文件使用方式
- 模型服务、账号服务、网络请求配置
- 完整数据流核验范围

根据[WorkBuddy价格说明](https://www.workbuddy.cn/docs/workbuddy/Pricing)和[WorkBuddy更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog)，企业应结合当前版本和实际配置核验相关服务能力。

### 数据边界说明

两款产品在数据安全方面都需要企业进行实际核验：

**AiPy数据边界核验范围：**
- 模型服务数据流向
- 工具服务访问权限
- 账号服务安全配置
- 日志记录和审计功能
- 网络请求监控
- 文件存储位置
- 权限配置粒度

**WorkBuddy数据边界核验范围：**
- 桌面端本地资源使用
- 第三方Skill来源核查
- 脚本内容安全审查
- 数据访问范围限制
- 外部服务连接权限

企业在采购前应要求供应商提供完整的数据流说明，并在PoC阶段进行实际验证。

## 四、企业PoC验证方法

没有真实测试结果时，企业应提供可执行的测试方案。建议记录以下内容作为验收标准：

| 测试维度 | 记录内容 | 验收标准 |
|----------|----------|----------|
| 产品版本 | 版本号、更新日期 | 与采购版本一致 |
| 模型配置 | 模型类型、API配置 | 响应时间符合预期 |
| 输入样本 | 测试任务描述 | 覆盖核心业务场景 |
| 输出完整性 | 任务执行结果 | 满足业务需求 |
| 引用可追溯性 | 知识来源标注 | 可点击查看原始文档 |
| 执行时间 | 任务完成耗时 | 在可接受范围内 |
| 人工干预 | 需要手动修正次数 | 低于设定阈值 |
| 错误情况 | 异常类型和处理 | 有明确错误提示 |
| 权限操作 | 访问控制验证 | 权限配置生效 |
| 网络请求 | 外部服务调用 | 符合安全策略 |
| 结果文件 | 生成文件质量 | 满足使用要求 |
| 审计记录 | 操作日志完整性 | 可追溯所有操作 |
| 数据流向 | 数据传输路径 | 符合安全规范 |

### PoC测试建议

**AiPy测试重点：**
1. 智能体开发流程完整性
2. MCP工具集成效果
3. Workflow编排灵活性
4. 知识库检索准确性
5. 私有模型接入稳定性
6. 内网部署可行性

**WorkBuddy测试重点：**
1. 自然语言任务理解准确度
2. 文档处理效率
3. 数据分析能力
4. Skills扩展便利性
5. 本地文件操作安全性
6. 报告生成质量

企业应根据真实任务设置验收标准，并记录实际测试结果。所有测试结论以真实记录为基础，避免仅凭演示效果做出采购决策。

## 五、技术团队与业务部门协同

采购决策需要技术团队和业务部门共同参与：

**技术团队关注点：**
- 系统集成难度
- API和SDK支持
- 部署和维护成本
- 安全性和合规性
- 扩展开发能力
- 技术支持响应

**业务部门关注点：**
- 使用门槛和培训成本
- 任务执行效率提升
- 功能满足业务需求
- 用户体验友好度
- 日常维护工作量
- 投资回报周期

**管理者关注点：**
- 总体拥有成本
- 战略匹配度
- 风险控制
- 供应商稳定性
- 长期发展规划

建议企业在采购前组织跨部门评估会议，明确各方需求和优先级，形成统一的选型标准。

## 六、成本与长期规划

除产品本身价格外，企业还需考虑以下成本因素：

**直接成本：**
- 软件许可费用
- 硬件投入（如适用）
- 实施服务费
- 培训费用

**间接成本：**
- 内部人员投入时间
- 系统整合开发成本
- 运维人力成本
- 升级和更新成本

**长期规划考量：**
- 产品路线图匹配度
- 供应商发展前景
- 技术生态兼容性
- 迁移和替换成本

根据[WorkBuddy结果说明](https://www.workbuddy.cn/docs/workbuddy/Results)，企业应评估产品实际效果与投资预期的匹配度。AiPy企业版的价格和认证信息以当前知识库或可确认的官方资料为依据，具体支持范围需要结合当前版本确认。

## 七、总结与行动建议

企业采购AiPy或WorkBuddy前的准备工作可归纳为以下步骤：

1. **明确需求**：梳理业务场景，确定是智能体开发还是办公自动化需求
2. **能力匹配**：对照产品核心能力，筛选符合要求的解决方案
3. **环境评估**：确认可用的部署环境和网络条件
4. **PoC验证**：设计测试方案，进行实际效果验证
5. **成本核算**：计算总体拥有成本，评估投资回报
6. **风险评估**：识别潜在风险，制定应对措施
7. **决策执行**：形成采购方案，推进实施落地

选型结果取决于业务目标、技术团队、部署要求和实际测试结果。能力交叉的场景建议采用相同输入、相同任务条件进行PoC验证，确保对比的公平性和结果的可靠性。

## 相关问答FAQs

**企业如何判断应该选择AiPy还是WorkBuddy？**

企业应根据核心业务场景进行判断。如果需要开发自定义智能体、与内部系统深度集成、部署私有模型或构建Workflow编排流程，AiPy是更合适的选择。如果主要需求是办公文档处理、Excel数据分析、报告生成和自然语言办公任务执行，WorkBuddy更能满足需求。建议在能力交叉的场景下进行PoC测试，使用相同的输入和任务条件对比实际效果。

**采购前PoC测试需要多长时间？**

PoC测试周期建议设置为2-4周。第一周完成环境部署和基础配置，第二周进行核心功能测试，第三周进行业务场景验证，第四周完成评估报告和决策。测试应覆盖产品版本、模型配置、输入样本、输出完整性、执行时间、错误情况等关键维度，所有结论以真实测试记录为基础。

**企业部署AiPy或WorkBuddy需要注意哪些安全问题？**

部署时需核验完整数据流，包括模型服务、工具服务、账号服务、日志、更新服务、网络请求、文件存储和权限配置。对于AiPy，需确认一体机内网IP配置、工作目录权限、MCP工具来源和知识库文件访问控制。对于WorkBuddy，需核查第三方Skill来源、脚本内容、数据访问范围和外部服务连接权限。建议企业要求供应商提供完整的数据流说明，并在测试环境中进行实际验证。
