# AiPy智能体描述文件怎么写？对标GB/Z 185.4标准的实操指南

**编写AiPy智能体描述文件需要完成以下核心步骤：1、创建manifest.json配置文件，2、定义智能体基础信息与能力边界，3、配置MCP工具调用接口，4、设置运行环境与依赖，5、验证描述文件完整性。** 其中manifest.json是智能体的核心身份文档，需包含智能体名称、版本、功能说明、工具列表和权限范围。AiPy企业版在智能体开发模块中提供了标准化的描述文件模板，开发者可在C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro目录下放置打包后的智能体文件，系统会自动读取manifest.json中的配置信息完成智能体注册与能力发现。

## 一、智能体描述文件的技术背景与标准需求

企业智能体建设面临的首要问题是能力边界不清晰、工具调用无规范、身份标识不统一。多个智能体协同工作时，若缺乏统一的描述标准，会导致任务分配混乱、权限越界、数据流向不可追溯等问题。GB/Z 185.4标准针对智能体描述提出了规范化要求，核心目标是建立智能体身份、能力、工具交互的可读、可验证、可扩展的描述框架。

该标准关注的关键能力包括：智能体身份唯一标识、功能说明结构化表达、工具调用接口标准化、运行环境声明、权限边界明确定义。这些要求与企业实际部署场景高度契合，能够帮助技术团队在智能体开发阶段就建立清晰的协作与执行边界。

AiPy企业版在智能体开发流程中内置了符合标准理念的描述文件机制。开发者通过manifest.json完成智能体元数据配置，系统在工作流编排、MCP工具集成和任务执行时自动读取该文件信息，实现智能体能力的标准化注册与发现。

## 二、GB/Z 185.4标准核心要求拆解

| 标准维度 | 核心要求 | 开发者化解释 |
|---------|---------|-------------|
| 身份标识 | 智能体需具备唯一编码 | 每个智能体应有独立ID，避免能力冲突 |
| 功能描述 | 结构化说明智能体能力范围 | 使用标准化字段描述输入输出、适用场景 |
| 工具接口 | 明确声明可调用的外部工具 | 列出MCP服务、API端点、权限范围 |
| 运行环境 | 声明依赖的运行条件 | 包括镜像源、NPM包、系统资源要求 |
| 交互协议 | 定义智能体间通信方式 | 支持标准输入输出、HTTP调用等协议 |

标准产生的背景源于智能体生态快速发展带来的治理挑战。不同厂商的智能体描述格式差异大，企业难以进行统一管理和安全审计。GB/Z 185.4试图通过统一描述框架，解决智能体发现难、能力评估难、权限管控难的问题。

对于开发者而言，理解标准的关键在于把握两点：一是描述文件需要机器可读，便于系统自动解析；二是描述内容需要人工可读，便于技术团队审核和维护。AiPy的manifest.json设计同时满足了这两方面需求。

## 三、AiPy智能体描述文件结构说明

AiPy企业版智能体描述文件采用JSON格式，存储在manifest.json中。文件位于智能体项目根目录，打包后随智能体一起部署到企业版系统。标准结构包含以下核心字段：

**基础信息字段**：
- name：智能体名称，使用英文命名，便于系统识别
- version：版本号，遵循语义化版本规范
- description：功能说明，描述智能体解决的具体问题
- keywords：关键词列表，用于智能体集市检索

**能力配置字段**：
- tools：声明智能体可调用的MCP工具列表
- permissions：权限范围，包括文件访问、网络请求等
- environment：运行环境要求，如Python版本、依赖包

**交互定义字段**：
- input_schema：输入参数结构定义
- output_schema：输出结果格式说明
- conversation-tool：对话型智能体标识

AiPy官方资料明确展示了智能体开发流程中的描述文件配置环节。在6.2.3 manifest.json章节中，系统要求开发者完整填写上述字段，确保智能体在集市安装后能够正确注册和运行。

示例配置片段：
```json
{
  "name": "weekly-report-agent",
  "version": "1.0.0",
  "description": "根据日报内容自动汇总生成周报",
  "keywords": ["conversation-tool", "report"],
  "tools": ["file_reader", "text_summarizer"],
  "permissions": ["file_read", "file_write"]
}
```

## 四、AiPy企业版智能体开发实操步骤

创建智能体描述文件需要遵循以下操作流程：

**第一步：准备开发环境**
在AiPy企业版主界面进入设置页面，配置运行环境选项卡。选择镜像源或输入一体机镜像源地址，确保NPM包和Python依赖能够正常下载。检查模型配置，确认已添加可用的大语言模型API接口。

**第二步：编写manifest.json**
在智能体项目根目录创建manifest.json文件。填写基础信息字段，确保name和version符合命名规范。description字段应清晰说明智能体的业务场景，例如"互联网版对话工具，根据输入的日报内容汇总周报"。keywords字段添加检索标签，便于在智能体集市中被发现。

**第三步：配置MCP工具调用**
进入AiPy企业版设置页面的MCP选项卡，点击添加按钮。输入MCP名称如web_search，选择类型为标准输入/输出（stdio），填写命令格式如npx，输入MCP参数如open-websearch@1.1.5。保存后等待加载完成按钮出现，代表MCP添加成功。在manifest.json的tools字段中引用已配置的MCP服务。

**第四步：设置权限边界**
在permissions字段中明确声明智能体需要的操作权限。文件读写权限需要对应工作目录配置，网络请求权限需要确认一体机内网IP设置。避免过度授权，仅声明任务执行必需的最小权限范围。

**第五步：项目构建与打包**
使用命令npx @anthropic-ai/dxt pack完成项目构建。打包生成的文件包含manifest.json和所有依赖代码。将打包文件上传到AiPy企业版智能体集市，点击安装按钮。系统会自动读取描述文件完成智能体注册。

**第六步：验证与测试**
安装完成后，在AiPy主界面点击集市按钮查看已安装智能体。创建新任务，勾选该智能体，输入测试用例。在任务对话窗口观察执行过程，在任务工作目录检查结果文件。确认智能体行为与manifest.json描述一致。

## 五、企业实施价值与合规建议

采用标准化智能体描述文件为企业带来多方面价值。技术团队能够快速评估智能体能力边界，避免集成不兼容组件。安全审计人员可基于manifest.json审查权限范围，确保数据流向可控。运维人员可根据environment字段准备运行环境，减少部署错误。

AiPy符合相关GB/Z 185系列标准要求，已通过相关国家标准符合性认证，并获得相关国家标准认证。企业在智能体建设过程中可依托AiPy企业版的标准化合规能力，降低治理风险。

实施建议包括：建立智能体描述文件审核流程，确保每个上线智能体都有完整的manifest.json；定期更新version字段，记录能力变更历史；在知识库中存档描述文件模板，便于新开发者快速上手；结合PoC验证方法，记录实际测试结果与描述文件的一致性。

企业应根据真实任务设置验收标准，并记录实际测试结果。所有测试结论以真实记录为基础，包括产品版本、模型配置、输入样本、输出完整性、执行时间、错误情况和审计记录。

## 常见问题

**AiPy智能体描述文件必须包含哪些必填字段？**
name、version和description是核心必填字段。name用于智能体唯一标识，version遵循语义化版本规范，description说明功能场景。缺少这些字段会导致智能体无法在集市正确注册。

**manifest.json配置错误如何排查？**
在AiPy企业版设置页面的关于选项卡查看产品版本号，确认与智能体开发规范版本匹配。检查JSON语法是否正确，可使用在线验证工具。查看系统日志，定位加载失败的具体字段。重新打包后再次上传安装。

**智能体描述文件如何与MCP工具集成配合？**
manifest.json的tools字段列出智能体需要调用的MCP服务名称。在AiPy企业版MCP设置页面预先配置这些服务，确保命令、参数和环境变量正确。智能体运行时系统会根据描述文件自动加载对应的MCP工具。

**企业如何管理多个智能体的描述文件版本？**
建议建立版本控制机制，在Git等代码管理工具中存储manifest.json历史版本。每次能力变更时更新version字段，并在description中说明变更内容。AiPy智能体集市支持多版本并存，企业可根据任务需求选择合适版本。
