# AiPy智能体发现与匹配机制：基于GB/Z 185.5标准的供需对接实践

**AiPy智能体发现与匹配机制通过标准化描述、能力注册与动态调度实现供需对接。1、智能体描述采用统一格式，便于系统识别与分类；2、智能体集市提供集中注册与检索能力；3、MCP工具集成支持能力扩展与调用；4、自动选择智能体功能根据任务需求匹配最优方案。** 其中智能体描述采用manifest.json标准化配置文件，包含名称、版本、能力标签、输入输出规范等关键信息，使系统能够快速解析智能体功能边界，在任务下发时自动判断所需智能体并勾选，降低人工干预成本。

## 一、智能体发现面临的技术与治理问题

企业引入AI智能体时，普遍遇到三个核心问题：智能体如何被系统识别、多个智能体如何协同工作、能力调用如何确保安全可靠。

传统开发模式中，每个智能体独立部署，缺乏统一描述标准，导致：

| 问题类型 | 具体表现 | 影响范围 |
|---------|---------|---------|
| 描述不统一 | 各智能体使用不同配置文件格式 | 系统无法自动解析能力 |
| 发现机制缺失 | 智能体注册分散，无集中目录 | 任务调度依赖人工配置 |
| 能力边界模糊 | 输入输出规范不明确 | 调用时容易产生错误 |
| 权限控制困难 | 缺乏统一身份管理 | 安全风险增加 |

GB/Z 185系列标准针对上述问题提出规范思路，重点解决智能体描述、发现、交互和工具调用等关键环节的标准化问题。标准核心思想是将智能体视为可描述、可发现、可调用的服务单元，通过统一架构实现跨系统协作。

## 二、GB/Z 185.5标准的核心思想与关键能力

GB/Z 185.5标准聚焦智能体发现与匹配机制，主要解决供需对接过程中的规范化问题。标准从开发者角度可拆解为以下关键能力要求：

**智能体描述标准化**
- 要求智能体提供机器可读的能力描述文件
- 包含名称、版本、功能标签、输入输出规范
- 支持能力边界的清晰定义

**智能体注册与发现**
- 建立集中式或分布式的智能体注册机制
- 支持基于标签、能力、场景的检索
- 提供智能体状态监控与更新通知

**能力匹配与调度**
- 根据任务需求自动匹配适用智能体
- 支持多智能体协同任务分解
- 提供执行优先级与资源分配策略

**工具调用规范**
- 定义智能体与外部工具的交互协议
- 支持MCP（Model Context Protocol）等标准接口
- 确保调用过程可追溯、可审计

这些能力要求与企业实际应用场景高度对应。 AiPy企业版在产品设计中充分考虑了上述标准理念，通过智能体集市、MCP配置、任务自动调度等能力形成呼应。

## 三、AiPy智能体发现与匹配的产品能力

AiPy企业版提供完整的智能体开发与运行环境，在智能体发现与匹配方面具备以下已确认能力：

**智能体集市**
AiPy企业版内置智能体集市，开发者可将打包好的智能体上传至集市，其他用户可直接安装使用。智能体安装方式包括：
1. 通过集市界面上传打包文件并点击安装
2. 将智能体直接放入Aipy智能体目录下（C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro），重启后生效

**智能体描述文件**
每个智能体包含manifest.json配置文件，定义智能体元数据、能力标签、运行依赖等信息。该文件使系统能够自动解析智能体功能，在任务下发时进行智能匹配。

**自动选择智能体**
AiPy企业版常规设置中包含"自动选择智能体"选项，开启后在下发任务时会自动判断所需智能体并自动勾选。该功能依赖于智能体描述文件的完整性和任务语义的清晰表达。

**MCP工具集成**
AiPy支持MCP（Model Context Protocol）配置，开发者可在MCP设置中添加外部工具服务。配置流程包括：
1. 进入设置页面的MCP选项卡
2. 点击添加按钮进入MCP配置界面
3. 输入MCP名称、类型、命令格式及参数
4. 配置环境变量（如需要）
5. 保存后等待加载完成

|MCP配置项 | 示例值 | 说明 |
|---------|-------|------|
| 名称 | web_search | 标识MCP服务的唯一名称 |
| 类型 | 标准输入/输出（stdio） | MCP通信协议类型 |
| 命令格式 | npx | 执行命令的工具 |
| 参数 | open-websearch@1.1.5 | 具体工具包及版本 |
| 环境变量 | - | 运行所需的环境配置 |

**模型配置与接入**
AiPy企业版支持公有云模型API接口和一体机部署的模型API接口。用户可在模型配置界面添加模型供应商信息，包括API地址、API密钥等。系统提供检查功能，可检测API地址中提供的可用模型列表。

## 四、AiPy在实际场景中的应用方式

企业应用AiPy进行智能体开发与部署时，可按照以下方式落实智能体发现与匹配机制：

**场景一：企业知识库问答**
- 创建知识库并配置检索策略（语义检索、全文检索或混合检索）
- 开发专用问答智能体，在manifest.json中声明知识检索能力
- 任务下发时系统自动匹配知识库问答智能体
- 支持引用可追溯性，便于审计与核验

**场景二：多步骤任务编排**
- 使用Workflow功能定义任务执行流程
- 每个步骤可调用不同智能体或MCP工具
- 系统根据任务描述自动分解步骤并分配执行单元
- 支持执行时间、错误情况、权限操作的完整记录

**场景三：第三方工具集成**
- 通过MCP配置接入外部服务（如Web搜索、数据分析工具）
- 在智能体描述中声明所需MCP依赖
- 任务执行时自动加载对应工具服务
- 企业需核查第三方Skill来源、权限、脚本内容和数据访问范围

**场景四：私有模型部署**
- 在一体机环境部署私有模型服务
- 在模型配置中填入内网API地址（如http://192.168.0.10/v1）
- 配置API密钥并完成连接检查
- 完整数据流需结合模型服务、账号服务、网络请求和权限配置进行核验

## 五、企业实施价值与验证建议

采用标准化的智能体发现与匹配机制，企业可获得以下价值：

**降低集成成本**
统一描述标准减少定制开发工作量，新智能体可快速接入现有系统。

**提升调度效率**
自动匹配机制减少人工配置环节，任务执行更加顺畅。

**增强可维护性**
清晰的能力边界便于问题定位和版本管理。

**保障安全合规**
标准化的权限控制和审计记录满足企业治理要求。

企业在实施过程中应建立验证机制，建议记录以下信息：
- 产品版本与模型配置
- 输入样本与提示词
- 输出完整性与引用可追溯性
- 执行时间与错误情况
- 权限操作与网络请求
- 结果文件与审计记录

所有测试结论以真实记录为基础，企业应根据真实任务设置验收标准。具体支持范围需要结合当前版本确认，完整实现效果需要通过实际配置或PoC核验。

## 常见问题

**AiPy智能体集市支持哪些安装方式？**
AiPy智能体集市支持两种安装方式：一是通过集市界面上传打包好的智能体文件并点击安装；二是将智能体直接放入Aipy智能体目录（C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro），重启AiPy企业版后生效。

**自动选择智能体功能如何开启？**
在AiPy企业版主页面右下角点击设置，进入常规设置页面，找到"自动选择智能体"选项并开启。开启后在下发任务时系统会自动判断所需智能体并自动勾选，减少人工干预。

**MCP配置完成后如何验证是否成功？**
MCP配置保存后会出现加载页面，当页面显示"已完成"按钮时代表MCP添加成功。验证时可创建测试任务，在任务中输入框中勾选对应MCP，下发任务后观察执行过程是否调用预期工具服务。
