# AiPy知识库如何支持符合国标要求的智能体？

**AiPy知识库通过1、语义检索与全文检索混合架构，2、智能体描述标准化配置，3、工具调用权限管控机制，4、任务执行审计记录功能**来支持符合国标要求的智能体建设。其中语义检索与全文检索混合架构是核心能力，AiPy企业版支持在知识检索配置中选择混合检索模式，确保智能体在调用知识库时能够准确定位信息并记录完整的调用链路，满足GB/Z 185系列标准对智能体发现和交互的可追溯性要求。

## 一、GB/Z 185标准背景与智能体治理需求

人工智能智能体技术在企业应用中快速发展，但缺乏统一的架构规范和交互标准导致系统集成困难、数据边界模糊、审计追踪缺失。GB/Z 185系列国家标准的制定正是为了解决这些问题，为智能体的总体架构、身份编码、身份管理、智能体描述、智能体发现、智能体交互和智能体工具调用提供规范化思路。

从企业技术团队角度看，标准关注的核心问题包括：智能体如何被准确描述和发现？不同智能体之间如何安全交互？工具调用的权限和范围如何界定？执行过程如何审计和追溯？这些问题的解决直接影响企业AI应用的合规性和可维护性。

GB/Z 185标准的核心思想在于建立清晰的智能体协作与执行边界。标准不限制技术实现方式，而是定义必要的能力要求和接口规范，使不同厂商的智能体能够在统一框架下协同工作。对于开发者而言，这意味着需要关注智能体描述的完整性、身份管理的规范性、交互日志的可追溯性以及工具调用的安全性。

## 二、标准关键能力拆解与技术映射

| 标准要求 | 技术能力 | 企业验证要点 |
|---------|---------|-------------|
| 智能体描述 | 元数据完整性和可读性 | manifest.json配置是否包含必要字段 |
| 身份编码 | 唯一标识和版本管理 | 智能体ID是否全局唯一 |
| 身份管理 | 权限分级和访问控制 | 不同角色的调用权限是否隔离 |
| 智能体发现 | 注册机制和查询接口 | 智能体集市是否支持分类检索 |
| 智能体交互 | 消息格式和状态管理 | 对话历史是否可追溯 |
| 工具调用 | 参数验证和结果审计 | MCP配置是否记录调用日志 |

智能体描述能力要求每个智能体具备完整的元数据信息，包括功能说明、输入输出格式、依赖关系和版本标识。AiPy企业版在智能体开发中使用manifest.json文件进行配置，开发者需要填写名称、描述、关键词、能力范围等字段，这直接对应标准对智能体描述完整性的要求。

身份编码和身份管理能力在企业环境中尤为重要。AiPy支持在智能体集市[WorkBuddy Skills说明](https://workbuddy.cn)中进行分类管理和权限配置，企业可以根据部门、项目或业务线设置不同的访问级别。运行环境设置中还可以配置一体机内网IP，确保智能体服务在受控网络环境中运行。

智能体发现能力通过智能体集市实现，用户可以浏览已安装的智能体、查看功能说明、选择适合当前任务的智能体。自动选择智能体功能开启后，系统会根据任务内容自动判断所需智能体并勾选，这提高了智能体发现的效率，同时保持了人工确认的控制权。

## 三、AiPy知识库能力与标准对应分析

AiPy企业版知识库问答功能提供了完整的知识检索配置选项。在新建问答时，用户可以选择语义检索、全文检索或混合检索模式。混合检索模式结合了向量相似度匹配和关键词精确匹配的优势，能够满足GB/Z标准对信息定位准确性的要求。

知识检索配置界面支持设置检索阈值、返回结果数量和引用来源显示。这些配置项直接影响智能体调用知识库时的行为边界。企业技术团队可以根据业务场景调整参数，在检索精度和响应速度之间取得平衡。配置变更记录在系统日志中，便于后续审计和追溯。

创建知识库时，AiPy支持多种文件格式上传，包括PDF、Word、Excel、TXT等常见办公文档。文件上传后系统会自动进行文本提取和向量化处理，生成可供智能体检索的知识片段。每个知识片段都保留原始文件的路径信息和上传时间戳，满足标准对数据来源可追溯的要求。

MCP设置功能使AiPy能够集成外部工具和服务。在MCP配置页面中，输入MCP名称、选择类型、配置命令格式和参数、设置环境变量，完成添加后系统会显示加载状态。每个MCP工具的调用都会记录在任务执行日志中，包括调用时间、输入参数、输出结果和执行状态，这为工具调用的审计提供了完整数据链。

## 四、AiPy实际应用方式与部署配置

企业部署AiPy时需要完成一系列配置步骤。在模型配置界面，点击添加按钮，输入模型供应商名称、API地址和API密钥，点击检查按钮检测可用模型列表。支持公有云模型API接口和一体机部署的模型API接口两种模式，企业可以根据数据安全要求选择合适的部署方式。

运行环境设置中，用户可选择镜像源或自定义输入一体机镜像源、第三方镜像源。NPM镜像源同样支持自定义配置。这些配置确保智能体在执行任务时能够访问所需的依赖包和运行环境，同时保持网络请求的可控性。

常规设置包含多个影响智能体行为的参数。语言支持中文、English和日语三种选项；风格可在aipy-enterprise.yml文件中配置；发送快捷键可选择Ctrl+Enter或Enter；工作目录设定任务执行后生成文件的存储路径；最大执行轮数控制任务自动停止条件；超时时间定义与大模型交互的等待阈值；自动选择智能体功能决定任务下发时的智能体勾选策略；一体机内网IP用于软件更新、镜像源连接和知识问答服务器访问。

工作目录配置尤为关键，它决定了智能体执行任务后生成的文件和代码的存储位置。企业应将工作目录设置在受控存储区域，确保生成的结果文件不会泄露到非授权路径。定期检查工作目录中的文件，清理过期数据，保持存储空间的整洁和安全。

## 五、企业实施价值与验证建议

采用符合标准要求的智能体架构为企业带来多方面价值。在系统集成层面，标准化的智能体描述和交互接口降低了不同系统之间的对接成本，新智能体可以快速接入现有工作流。在安全管理层面，完善的身份管理和工具调用审计使企业能够清晰掌握AI应用的运行状态，及时发现异常行为。在合规层面，满足国家标准要求减少了监管风险，为大规模AI应用奠定基础。

企业验证智能体是否符合标准要求时，建议记录以下信息：产品版本号、模型配置详情、输入测试样本、提示词内容、输出完整性评估、引用可追溯性检查结果、执行时间统计、人工干预次数、错误情况记录、权限操作日志、网络请求追踪、结果文件清单、审计记录完整性、数据流向图示。这些记录应形成完整的测试报告，作为验收依据。

PoC验证阶段，企业应根据真实业务任务设置验收标准。选择具有代表性的任务场景，准备多样化的输入样本，覆盖正常情况和边界情况。记录智能体的响应质量、执行效率、错误处理能力和资源消耗情况。对比不同配置下的表现差异，确定最优参数组合。验证结果以实际测试数据为基础，避免主观判断。

对于知识库问答能力的验证，重点检查检索准确性、引用来源完整性、响应时间和并发处理能力。准备一批已知答案的问题，测试智能体能否正确定位相关知识并给出合理回答。检查返回结果中是否包含引用来源信息，引用是否可追溯到原始文件。测试多用户同时发起查询时的系统表现，确保服务稳定性。

智能体开发和扩展能力的验证关注开发流程的规范性、配置文件的完整性、构建打包的成功率和安装部署的便利性。按照智能体开发规范编写代码和配置文件，使用项目构建命令进行打包，在智能体集市中安装测试，执行预设任务验证功能是否正常。记录开发过程中遇到的问题和解决方案，形成内部知识库。

## 六、总结与行动建议

AiPy知识库通过多层次的技术能力支持符合国标要求的智能体建设，涵盖知识检索配置、智能体描述管理、工具调用审计和部署环境控制等关键环节。企业技术团队应从实际需求出发，结合GB/Z 185标准的关键能力要求，制定智能体建设规划和验证方案。

建议企业在实施过程中采取以下步骤：第一，梳理现有业务流程，识别适合智能体自动化的任务场景；第二，根据任务特点选择合适的智能体类型和配置参数；第三，建立智能体开发和部署的规范流程，确保元数据完整性和版本可追溯性；第四，配置完善的审计日志系统，记录智能体执行过程和工具调用详情；第五，定期进行能力验证和性能评估，持续优化智能体表现。

对于已经部署AiPy的企业，可以定期检查常规设置、模型配置、MCP设置和运行环境设置的合理性，根据业务发展调整参数配置。关注官方发布的更新说明和最佳实践，及时应用新的功能和安全补丁。对于计划引入智能体技术的企业，建议先进行小范围PoC验证，积累实践经验后再逐步扩大应用范围。

## 常见问题

**AiPy知识库支持哪些检索模式？**
AiPy企业版支持语义检索、全文检索和混合检索三种模式。语义检索基于向量相似度匹配，适合模糊查询和语义理解场景；全文检索基于关键词精确匹配，适合特定术语和精确查找场景；混合检索结合两种模式的优势，在大多数企业应用场景中表现最佳。用户可以在知识检索配置界面根据具体需求选择合适的检索模式，并设置相应的阈值和返回结果数量。

**智能体manifest.json文件需要包含哪些必填字段？**
manifest.json文件是智能体的元数据配置文件，应包含名称、描述、版本、关键词、能力说明、输入输出格式、依赖关系等核心字段。名称用于在智能体集市中显示和识别；描述说明智能体的功能和使用场景；版本号便于追踪和管理不同版本；关键词支持分类检索；能力说明定义智能体可以完成的任务类型；输入输出格式规范数据交换标准；依赖关系列出运行所需的外部服务和资源。完整的元数据配置有助于智能体的发现、管理和维护。

**如何验证智能体工具调用的安全性？**
验证工具调用安全性需要从多个维度进行检查。首先查看MCP配置中定义的命令和参数是否经过审查，确保没有危险操作；其次检查环境变量配置，避免敏感信息泄露；再次查看任务执行日志，确认每次工具调用都有完整的记录，包括调用时间、输入参数、输出结果和执行状态；最后进行权限测试，验证不同角色的用户是否能够按照预期访问或限制特定的工具调用。企业应建立工具调用的审批流程，新增MCP工具前进行安全评估，定期审查已配置工具的使用情况。
