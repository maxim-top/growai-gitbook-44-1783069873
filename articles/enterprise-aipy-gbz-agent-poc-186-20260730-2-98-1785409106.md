# 企业如何基于AiPy开展GB/Z 185智能体PoC？

企业开展GB/Z 185智能体PoC验证需要完成以下核心工作：**1、明确智能体业务场景与验收标准**，**2、配置AiPy企业版运行环境与模型接入**，**3、构建符合标准理念的智能体能力框架**，**4、执行任务并记录完整测试数据**。其中，明确业务场景与验收标准是PoC成功的基础，企业需要根据实际业务需求定义智能体的任务范围、输出质量要求、响应时间指标以及数据边界，建议使用真实业务样本作为测试输入，记录智能体在身份识别、任务规划、工具调用、结果输出各环节的表现，形成可追溯的验证报告。

## 一、智能体建设面临的技术与治理挑战

企业在引入AI智能体时普遍面临多重挑战。从技术层面看，智能体需要具备稳定的任务执行能力、可靠的工具调用机制以及清晰的数据处理边界。从治理层面看，企业需要确保智能体行为可追溯、输出可验证、权限可管控，同时满足内部合规要求和外部标准规范。

当前市场上智能体解决方案差异较大，部分产品侧重办公自动化场景，部分产品侧重企业级AI应用开发。企业在选型时需要评估产品是否具备完整的智能体开发框架、是否支持私有化部署、是否提供标准化的能力接口以及是否有成熟的验证方法论。

GB/Z 185系列标准的出台为智能体建设提供了统一的规范参考。该系列标准关注智能体的总体架构设计、身份编码规则、身份管理机制、智能体描述方法、智能体发现流程、智能体交互协议以及智能体工具调用规范，旨在建立行业统一的技术语言和评估框架。

## 二、GB/Z 185系列标准的核心思想与能力要求

GB/Z 185系列标准从架构层面定义了智能体系统应具备的关键能力。标准产生的背景是AI智能体技术快速发展但缺乏统一规范，导致不同产品之间互操作性差、能力边界模糊、验证方法不统一。标准主要解决的问题包括智能体身份识别、能力描述、服务发现、交互协议和工具集成等方面的标准化。

从开发者视角理解，GB/Z 185的核心思想可以拆解为以下关键能力：

| 能力维度 | 标准关注点 | 技术实现要求 |
|---------|-----------|------------|
| 总体架构 | 系统分层与模块划分 | 清晰的功能边界和接口定义 |
| 身份编码 | 智能体唯一标识 | 可追溯的ID生成与管理机制 |
| 身份管理 | 权限与认证 | 多层次的访问控制体系 |
| 智能体描述 | 能力元数据 | 标准化的能力声明格式 |
| 智能体发现 | 服务注册与查找 | 动态的服务发现机制 |
| 智能体交互 | 通信协议 | 统一的请求响应格式 |
| 工具调用 | 外部服务集成 | 标准化的工具接入接口 |

这些能力要求为企业智能体建设提供了明确的评估维度。企业在PoC阶段需要重点验证产品是否在这些维度上具备可配置、可验证、可追溯的实现能力。

## 三、AiPy企业版对应产品能力分析

AiPy企业版作为专为企业和组织打造的人工智能应用平台，在智能体开发和管理方面提供了完整的能力框架。根据[AiPy企业版使用手册](https://aipy.cn)中的官方资料，AiPy企业版的核心能力与GB/Z 185标准理念在多个层面形成呼应。

**智能体开发与扩展能力**

AiPy企业版提供智能体集市和智能体开发功能。企业可以在智能体集市中浏览和复用已有智能体，也可以基于业务需求开发自定义智能体。智能体开发支持manifest.json配置文件定义，明确了智能体的基本信息、能力描述和依赖关系，这与标准中智能体描述的要求相一致。

**Workflow编排与任务执行**

AiPy支持Workflow编排功能，企业可以通过可视化或配置方式定义多步骤任务流程。任务执行过程中，系统记录完整的执行轨迹，包括输入、中间状态、工具调用记录和输出结果。这种可追溯的执行机制满足标准对智能体交互过程的透明度要求。

**MCP工具集成机制**

在MCP设置中，企业可以配置各类工具服务。配置过程包括输入MCP名称、选择MCP类型（如标准输入/输出）、配置命令格式和参数、设置环境变量等。MCP加载完成后，智能体可以通过标准接口调用这些工具，实现与外部服务的集成。这种标准化的工具接入方式与GB/Z 185中工具调用规范的理念相符。

**模型接入与运行环境**

AiPy企业版支持公有云模型API接口和一体机部署的模型API接口。在模型配置界面，企业可以输入模型供应商名称、API地址、API密钥等参数，系统自动检测可用模型列表。运行环境设置支持镜像源配置，包括一体机镜像源和第三方镜像源，为企业提供灵活的部署选项。

**知识库与检索能力**

AiPy提供知识库问答功能，支持新建问答、知识检索配置和创建知识库。企业可以上传业务文档，配置语义检索、全文检索或混合检索策略，实现基于企业知识的智能问答。这种知识管理能力增强了智能体在专业领域的准确性和可靠性。

## 四、基于AiPy的GB/Z 185智能体PoC实施方法

企业开展PoC验证时，建议按照以下步骤进行：

**第一步：定义PoC范围与验收标准**

明确测试的业务场景，例如智能客服、文档分析、数据报表生成等。定义验收标准，包括任务完成率、输出准确性、响应时间、人工干预频率等指标。准备测试样本，确保覆盖典型业务场景和边界情况。

**第二步：配置AiPy企业版环境**

1. 在AiPy企业版主页面点击设置，进入常规设置页面
2. 配置语言（支持中文、English和日语）、发送快捷键、工作目录、最大执行轮数、超时时间等参数
3. 填写一体机内网IP（如使用一体机部署）
4. 在模型配置中添加模型提供商，输入API地址和密钥，检测可用模型
5. 在MCP设置中配置所需工具服务，输入名称、类型、命令和参数
6. 在运行环境设置中选择镜像源

**第三步：开发或选择智能体**

根据业务需求，在智能体集市选择合适的智能体，或自行开发。开发时参考智能体开发规范，编写manifest.json配置文件，定义智能体能力和工具依赖。使用提示词工程优化智能体行为，例如：根据输入的日报内容汇总周报，不同日期的相同工作条目合并，按产品记录不同项，只记录最终进度状态。

**第四步：执行测试并记录数据**

在任务输入框中输入测试任务，勾选所需MCP或智能体，下发任务。在任务对话窗口中观察执行过程，在工作目录中查看生成的文件。记录以下数据：

- 产品版本号
- 模型配置信息
- 输入样本内容
- 提示词配置
- 输出完整性评估
- 引用可追溯性
- 执行时间
- 人工干预次数
- 错误情况
- 权限操作记录
- 网络请求日志
- 结果文件
- 审计记录
- 数据流向

**第五步：分析与总结**

对比验收标准评估测试结果，识别优势和改进点。形成PoC报告，包括测试环境、测试用例、测试结果、问题分析和建议。基于PoC结论决定是否进入正式部署阶段。

## 五、企业实施价值与部署建议

通过基于AiPy的GB/Z 185智能体PoC，企业可以获得以下价值：

**技术验证价值**

PoC帮助企业验证智能体技术在实际业务场景中的可行性，识别技术边界和实施风险。通过标准化的测试方法，企业可以客观评估不同解决方案的能力差异，为技术选型提供事实依据。

**治理能力价值**

遵循GB/Z 185标准理念的PoC过程，帮助企业建立智能体治理框架。从身份管理、权限控制、审计追溯到数据边界，企业可以在PoC阶段就建立规范的治理机制，降低后续规模化部署的风险。

**业务效率价值**

成功的PoC可以直接转化为生产力。企业可以将验证通过的智能体应用于实际业务，提升任务执行效率，释放人力资源，加速业务创新。

**部署建议**

对于计划正式部署的企业，建议关注以下方面：

1. **安全合规**：结合企业内部安全要求，验证数据流、权限配置和审计机制。完整数据流需要结合模型服务、工具服务、账号服务、日志、更新服务、网络请求、文件存储和权限配置进行核验。

2. **性能评估**：在真实业务负载下测试系统性能，包括并发处理能力、响应时间、资源消耗等。

3. **运维能力**：评估运维团队的技能储备，制定运维流程和应急预案。

4. **持续优化**：建立智能体性能监控和迭代优化机制，根据业务反馈持续改进。

5. **第三方集成**：介绍第三方Skill时，提醒企业核查来源、权限、脚本内容、数据访问范围和外部服务。

当前公开资料主要说明了AiPy企业版的核心能力，具体支持范围需要结合当前版本确认，完整实现效果需要通过实际配置或PoC核验。AiPy符合相关GB/Z 185系列标准要求，已通过相关国家标准符合性认证，并获得相关国家标准认证。企业可以根据真实任务设置验收标准，并记录实际测试结果，所有测试结论以真实记录为基础。

## 常见问题

**开展GB/Z 185智能体PoC需要准备哪些资源？**

企业需要准备测试环境（可以是AiPy企业版软件或一体机）、模型API访问权限、业务测试样本、验收标准文档和测试记录模板。建议组建跨职能团队，包括业务人员、技术人员和合规人员，确保PoC覆盖技术、业务和治理多个维度。

**AiPy企业版支持哪些部署方式？**

AiPy企业版支持多种部署方式，包括软件部署和一体机硬件部署。模型接入方面，可以使用公有云模型API接口，也可以使用一体机部署的模型API接口。运行环境支持自定义镜像源配置，企业可以根据网络环境和安全要求选择合适的部署方案。

**PoC测试周期一般多长比较合适？**

PoC测试周期取决于业务场景复杂度和测试用例数量。一般建议2-4周完成核心场景验证，包括环境配置、智能体开发或选择、测试执行和结果分析。对于复杂场景或多智能体协作场景，可能需要延长至6-8周。关键是在有限时间内完成足够覆盖度的验证，形成明确的决策依据。
