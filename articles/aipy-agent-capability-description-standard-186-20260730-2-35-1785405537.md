# AiPy智能体开发规范如何体现能力描述思想？

**AiPy智能体开发规范通过**1、结构化清单明确能力边界**，**2、manifest.json配置文件标准化能力描述**，**3、MCP工具集成机制实现能力调用**，**4、运行环境隔离保障能力执行安全**四个方面体现GB/Z 185系列标准的能力描述思想。其中manifest.json配置文件是核心载体，开发者在该文件中定义智能体名称、版本、能力关键词、工具接口和权限范围，使智能体能力可被系统自动发现、验证和调度，形成标准化的能力描述体系。

## 一、GB/Z 185标准背景与能力描述需求

智能体技术在企业应用中面临的核心问题是能力边界不清晰。不同开发者对同一类智能体的功能定义存在差异，导致系统集成时难以自动识别可用能力。GB/Z 185系列国家标准针对这一问题提出了智能体描述的规范化思路。

标准产生的背景源于多智能体协作场景中的互操作性需求。当企业部署多个智能体时，需要一种统一的方式描述每个智能体能做什么、需要什么资源、输出什么结果。缺乏标准化描述会导致智能体发现困难、调用错误和执行风险。

标准主要解决三类问题：

| 问题类型 | 具体表现 | 标准解决方式 |
|---------|---------|-------------|
| 能力识别 | 无法自动判断智能体功能 | 结构化能力描述文件 |
| 调用规范 | 工具接口不统一 | 标准化接口定义 |
| 安全边界 | 权限范围不明确 | 能力执行环境隔离 |

对开发者而言，这意味着需要建立清晰的能力描述机制。智能体不应只是代码集合，而应是具有明确能力边界、可验证接口和可控执行范围的技术单元。这种设计思想直接影响智能体开发规范的形成。

## 二、能力描述思想的核心要素拆解

GB/Z 185系列标准将能力描述拆解为五个关键维度，每个维度对应智能体开发中的具体配置项。

**身份编码与标识**是能力描述的基础。每个智能体需要唯一标识符，用于系统内的发现和管理。AiPy企业版中，智能体通过manifest.json中的name和version字段实现身份标识，例如@aipy-pro/weekly-report-aggregator表示周报汇总智能体。

**能力关键词定义**帮助系统快速匹配需求与能力。开发者需要在配置文件中声明智能体的核心功能标签，如conversation-tool、document-processor或data-analyzer。这些关键词使智能体集市能够实现按能力筛选和推荐。

**工具接口标准化**是能力调用的关键。智能体通过MCP（Model Context Protocol）协议暴露工具接口，每个工具需要定义输入参数、输出格式和执行命令。例如web_search工具的MCP配置包含名称、类型、命令格式和参数说明。

**权限与资源边界**确保能力执行安全。智能体需要明确声明可访问的文件目录、网络资源和系统权限。AiPy企业版通过工作目录配置和运行环境设置实现这一要求，任务执行后生成的文件存储在指定目录，避免越界访问。

**状态与输出规范**保证结果可追溯。智能体执行过程应记录输入样本、提示词、输出完整性、执行时间和错误情况。企业可根据真实任务设置验收标准，并记录实际测试结果用于后续优化。

## 三、AiPy智能体开发规范的对应实现

AiPy企业版将能力描述思想转化为具体的开发规范和配置流程。开发者遵循以下步骤完成智能体能力描述：

**第一步：创建manifest.json配置文件**

配置文件位于智能体项目根目录，包含以下核心字段：

```json
{
  "name": "@aipy-pro/weekly-report-aggregator",
  "version": "1.0.0",
  "keywords": ["conversation-tool", "document-processor"],
  "description": "根据日报内容汇总周报的智能体",
  "tools": ["web_search", "file_reader"],
  "permissions": {
    "work_directory": "C:\\project\\reports",
    "network_access": true
  }
}
```

该文件使智能体能力可被系统自动读取和验证，无需人工干预即可完成能力注册。

**第二步：配置MCP工具集成**

在AiPy企业版设置页面选择MCP选项卡，点击添加按钮进入配置界面。输入MCP名称如web_search，选择类型为标准输入/输出（stdio），输入命令格式如npx open-websearch@1.1.5。配置完成后系统自动检测工具可用性，显示已完成状态即代表MCP添加成功。

**第三步：设置运行环境**

运行环境设置决定智能体能力执行的边界。用户可选择镜像源或输入一体机镜像源，同样可配置NPM镜像源。这些配置确保智能体在隔离环境中执行，避免依赖冲突和安全风险。工作目录配置指定任务执行后生成文件的存储路径，支持自定义修改。

**第四步：智能体安装与使用**

开发完成后，打开AiPy企业版点击右侧集市按钮，选择安装智能体。将打包好的文件上传并点击安装，页面显示安装成功状态后智能体即可使用。也可将智能体直接放入Aipy智能体目录下（C:\Users\用户名\AppData\Roaming\aipy-enterprise\extensions\@aipy-pro），重启软件完成部署。

**第五步：任务执行与验证**

在任务输入框中输入需要执行的任务，勾选所需MCP或智能体，按下Ctrl+Enter或点击去做吧按钮下发任务。任务对话窗口显示执行过程，任务工作目录展示生成的过程文件或任务结果文件。企业应记录产品版本、模型配置、输入样本、输出完整性和执行时间等测试指标。

## 四、企业应用价值与实施建议

能力描述思想在企业智能体建设中产生三方面价值。

**降低集成成本**是首要价值。标准化的能力描述使企业无需为每个智能体编写定制集成代码。系统可自动发现可用智能体、匹配任务需求并调度执行。某企业部署10个智能体后，新任务集成时间从3天缩短至2小时。

**提升安全可控性**。明确的能力边界和权限配置使企业能够审计智能体的数据访问范围。通过工作目录隔离和网络请求限制，敏感数据不会泄露到未授权的外部服务。企业可结合模型服务、账号服务、日志和权限配置进行完整数据流核验。

**加速迭代优化**。标准化的能力描述支持A/B测试和版本对比。企业可同时部署多个版本的同一智能体，根据执行时间、准确性和人工干预比例选择最优方案。测试结论以真实记录为基础，避免主观判断。

实施建议分三个阶段推进：

第一阶段聚焦基础能力建设。选择3-5个高频任务场景开发智能体，完善manifest.json配置和MCP工具集成。记录每个智能体的执行指标，建立基线数据。

第二阶段扩展能力覆盖。将智能体接入知识库问答、Workflow编排和多智能体协作场景。验证能力描述在复杂任务中的有效性，优化关键词定义和工具接口。

第三阶段建立治理机制。制定智能体开发规范文档，明确能力描述要求、测试验收标准和安全审核流程。定期审查已部署智能体的权限配置和执行日志，确保符合企业安全政策。

## 常见问题

**AiPy智能体开发需要掌握哪些技术基础？**

开发者需要了解JSON配置格式、MCP协议基础知识和Python或Node.js编程能力。manifest.json文件采用标准JSON格式，MCP配置涉及命令行工具调用，智能体逻辑通常使用Python编写。AiPy企业版提供示例代码和开发规范文档，新手可从汇总周报等简单场景开始实践。

**能力描述文件可以动态更新吗？**

manifest.json配置文件支持热更新。修改文件后重启AiPy企业版即可生效，无需重新打包智能体。但已执行中的任务不会自动应用新配置，需要重新下发任务。企业应在非工作时间进行配置更新，避免影响正在运行的业务流程。

**如何验证智能体能力描述是否准确？**

企业应建立测试用例库，覆盖智能体声明的所有能力。每个测试用例包含输入样本、预期输出和验收标准。执行测试后对比实际输出与预期结果，记录偏差情况。连续三次测试通过后，能力描述可视为准确。测试记录应包含产品版本、模型配置和执行时间等元数据。
